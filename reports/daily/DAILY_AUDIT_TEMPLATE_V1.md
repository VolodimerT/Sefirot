# SEFIROT daily audit template v1

The daily report must always contain: (1) data coverage and provenance, (2) confirmed settlement summary, (3) original decision versus result and errors, (4) risk concentration and stale-data issues, (5) **Improvement and optimization backlog**, (6) next-day priorities, (7) verified archival checkpoint.

## Mandatory improvement and optimization backlog

| ID | Priority | Observed defect | Module / proposed work | Acceptance test | Status |
|---|---|---|---|---|---|
| SFR-... | P0/P1/P2 | specific evidence, no hindsight | specific non-breaking change | reproducible pass/fail | PROPOSED/IN_PROGRESS/VERIFIED/BLOCKED |

Do not equate a winning coupon with validated model advantage. Keep old seals and CORE/Policy status unchanged. A model enhancement requires a separate independently verified test. Prioritize correlated exposure caps, stale LIVE data fail-closed, Asian PUSH/VOID settlement accuracy, provider quote provenance, joint small-market model validation, and recoverable daily checkpoints. Do not silently enable betting execution.

## Archival procedure

Create one dated version per completed daily audit (v1, then v2 for corrections); never overwrite original. Verify the saved content by reading it back and report the actual path plus commit/checksum. Keep personal financial slips, receipts, bank values and credentials in private archives, not in the public repository. Public repository reports should be sanitized engineering summaries only.

## Status discipline

An improvement listed in a daily report is a proposal, not an implemented feature. The next report must compare open/closed/backlogged item IDs from the previous day.
