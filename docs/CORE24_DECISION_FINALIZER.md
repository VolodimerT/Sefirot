# CORE 2.4 — финальный выбор и корректный риск на рынках с PUSH

Дата: 01.10.2026. Основа: main `96dd95861be6c11bbc450432ca280f9a4d2efd3f`, фактический CORE 2.3. Ветка `core24-audit-model-risk` при восстановлении указывала на тот же commit и не содержала отдельной реализации 2.4.

Прочитаны актуальные Foundation v0.1, задания P0/P1/P2, аудит 30 сентября и ответ CORE 2.3. P0-диагностика уже реализована: модельная вероятность остаётся главным неподтверждённым компонентом. Отрицательный benchmark и просмотренные 49 аудитных случаев не используются для выбора новых численных порогов.

## Конкретная проблема

1. При полном PASS top-level limiting_factors скрывал локальные причины отказов. Пользователь видел «нет допустимого основного рынка», хотя система могла иметь положительный Base EV с отрицательным stress или недостающей калибровкой.
2. При глобальном veto selected_market всё ещё мог быть заполнен. Это создавало впечатление рекомендации вопреки PASS.
3. Приоритет additional_assumptions был бинарным штрафом HANDICAP/TEAM_TOTAL. Такой порядок мог выбрать более слабую цену на 1X2 прежде более сильного допущенного командного тотала.
4. Риск использовал `low[WIN]` и `low[PUSH]` как единую вероятность. Категорийные нижние границы обычно не достигаются одновременно: риск мог получить отрицательный EV и нулевую ставку после уже положительного точного Low EV.

## Что реализовано

| Область | Поведение CORE 2.4 | Ограничение |
|---|---|---|
| Арбитр | Один допущенный рынок при BET; selected_market=null при PASS; screened_market хранит предварительный выбор | Допуск по-прежнему требует всех gates |
| Причины PASS | NO_EDGE, PRICE_FRAGILE, PRICE_RECHECK, NOT_EVALUABLE, RECALCULATE, RISK_LIMIT в карточке | Это объяснения, verdict остаётся прежним |
| Лучший кандидат | Лучший кандидат положительного Base EV виден отдельно; сначала выбираются случаи, которым мешают только цена/свежесть | Не рекомендация, permission=false при PASS |
| Цена | Точный порог Base EV, Low EV и stress; PUSH учитывается отдельно | При некоторых диапазонах конечного порога нет; цена не гарантирует допуск |
| Рейтинг рынков | После спортивных gates: Low EV → stress EV → Base EV → меньшая P(LOSS) → меньше допущений → ключ | Исследовательское правило, превосходство на unseen данных не доказано |
| Риск | Худшее допустимое распределение из interval-simplex, затем существующие flat caps и ограничения экспозиции | Kelly остаётся диагностикой, отрицательный stress всё ещё блокирует |
| Пользовательский вывод | Короткий русский текст `demo/decide --text`, записанная карточка `explain ID --text` | JSON остаётся основным полным контрактом |
| Журнал | Карточка входит в immutable decision/hash/replay; explain открывает SQLite read-only | Архивные решения без карточки не переинтерпретируются |

Новая сефира не создана. Представление решения принадлежит Арбитру; ценовые расчёты используют существующую вероятностную математику; Летописец сохраняет обычный decision payload. Схема SQLite/Postgres не меняется, облачная миграция не нужна.

## Математика цены и риска

Для WIN/PUSH/LOSS:

`EV = P(WIN) × (K − 1) − P(LOSS)`.

Для целевого EV `t`: `K >= 1 + (P(LOSS) + t) / P(WIN)`.

При P(WIN)=0 и P(LOSS)+t>0 конечного K нет. PUSH не считается ни победой, ни проигрышем.

Low/High задают область допустимых распределений, а не отдельные вероятностные векторы. Линейный EV достигает минимума в вершине этой области. Ценовой порог — максимальный требуемый K по всем допустимым вершинам; размер ставки использует вершину с наименьшим EV при текущем K.

Контролируемый пример дефекта риска: Base=[0.45,0.40,0.15], Low=[0.40,0.30,0.10], High=[0.50,0.50,0.20], K=1.60. Покомпонентный Low даёт фиктивную P(LOSS)=0.30 и EV=−6%; допустимое худшее распределение [0.40,0.40,0.20] даёт EV=+4%. Новая версия исключает этот ложный нулевой риск. Это технический пример, не новый прогноз реального матча.

## Известные аудитные сценарии

Tamworth-подобный ввод Base EV +3.05%, stress −13.2% остаётся PASS и показывает AGGRESSIVE_VALUE. Taunton-подобный ввод +12.73%, stress −6.13% остаётся PASS и показывает FRAGILE_VALUE; порог только stress при исходной цене 2.30 равен примерно 2.4502. Калибровка, Low EV и остальные gates могут требовать большего или не допускать вход при любой цене.

Эти числа воспроизводятся как контролируемые контрактные тесты. Исходный предматчевый seal для реальных матчей не восстановлен. Их WIN не доказывает value или ошибку PASS.

## Валидация и threat model

- Вероятность не меняется при просмотре цены; функция карточки не читает результат, новую линию, внешние API или текущие часы.
- Candidate pool остаётся закрытым: максимум 7, один исход на семейство. Сравнение двух разных линий TEAM_TOTAL в одном пуле не заявляется реализованным.
- Даже если новый коэффициент превышает floor, divergence/freshness/recheck/risk могут блокировать вход; старый PASS не становится разрешением.
- Новая версия и policy fingerprint не наследуют старые calibrators/approvals/holdout. Для replay старых решений требуется архивная версия.
- Тестируются точные PUSH-формулы, невозможный конечный порог, согласованность worst-case distribution, критические veto, разница NO_EDGE/NOT_EVALUABLE, отсутствие допуска у research candidate, детерминизм и read-only explain.
- 191 исходный тест и новые проверки входят в release gate. Число и результат фактического запуска находятся в reports/TEST_REPORT.md.

## Следующий проверяемый этап

1. DATA: один спортивный провайдер и один провайдер цен. Спортивный импорт должен сохранять fixture/league IDs, kickoff, домашнюю/гостевую сторону, source/provider/independence_group, observed/published/received_at, raw_hash. Если историческое published_at неизвестно — явно UNKNOWN; нельзя заполнить его kickoff задним числом. Ключи только в окружении, не в Git.
2. P1: отдельный xG/xGA challenger с home/away и opponent adjustment; при отсутствии xG — честно иной источник/эксперимент, без выдачи голов за xG. SoS и player/GK impact пока не менять численно без данных и fit.
3. До невиденного периода зарегистрировать модель/данные/pool/policy hashes и сравнить два правила отбора на одних sports seals. 2.3 — archived baseline, 2.4 — challenger. Первичные метрики: Brier/log loss/calibration, завершённость анализа, доля NO_EDGE/NOT_EVALUABLE/PRICE_FRAGILE и paired admission differences. ROI/CLV/drawdown — дополнительные показатели, не одиночное доказательство.
4. Отдельно preregister graded-stress shadow policy и reduced-stake симуляции. Не снимать veto по результатам Tamworth/Taunton и не объявлять raw positive EV доказательством.
5. Только после unseen проверки обсуждать новый денежный допуск и D1. Экспресс 2–3 ноги требует независимости и общего учёта риска; этой сборкой он не реализован.

Статус: завершён инженерный этап финального вывода и риска; прогнозное преимущество CORE 2.4 ещё не доказано. Tavily не использовался.
