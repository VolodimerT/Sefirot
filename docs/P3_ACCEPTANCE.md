## Profile of the reported 300-fixture regression

Twenty paired samples per revision on Linux and Node 24, alternating which revision ran first. Each sample starts a fresh native PostgreSQL 19 cluster, forecasts and saves 300 matches, then settles the 300 original snapshots. Both revisions used the same HTTP adapter and fixture bytes. Values are median / nearest-rank p95 milliseconds. The profile separates transaction commit and times an uncontended advisory-lock round trip before invoking the RPC. Execution includes the local PostgreSQL wire round trip and JSONB input conversion. Transport residual subtracts the timed REST handler from worker HTTP read time; it also includes response serialization and event-loop delays. These measurements do not isolate production network latency.

## Admission and recovery evidence

The old manual validator accepted typed probabilities and review checkboxes without a source-backed candidate. P3 ties each leg to the exact autonomous fixture, line, price, cutoff and reviewed decision. The automated forecast and Paper admission paths also call the shared market review. Foul selection needs an independently reviewed main-market alternative and a verified death-test. Cards additionally require referee evidence. A positive portfolio must have positive net EV and two or three mutually reviewed independent fixtures (one for singles). Missing evidence gives PASS. The current producer and database authorize only PASS. Positive gate tests use synthetic reviewed candidates. A new database check enforces that ceiling for future tour receipts. Old receipts retain their original bytes.

The existing cron job queues at most one request at each of 17:00, 17:12 and 17:24 UTC. Each envelope expires in ten minutes. The SQL finish RPC checks the deadline and twenty-minute fixture cutoff under the existing advisory lock and after persistence. A late response rolls back the batch. Recovery suppresses optional gateway/odds and reserve-source calls. It permits at most two reads per primary CSV URL, at most 22 CSV attempts per retry. With a configured gateway or odds key, it defers new forecasts and reports PARTIAL. Settlements of previously sealed fixtures remain eligible. An outage lasting through all three slots requires a later eligible cycle. A database outage at the scheduled ticks can exhaust the opportunity to run.

Regression evidence on isolated fixtures:

- PGlite exercised owner death, repeated queue ticks, REST timeout, SQL rollback, delayed commit, lost commit reply, partial history, restart, budget exhaustion, stale delivery, rejected direct tour inserts and restoration of the prior job. Deno HTTP exercised authorization, sanitized upstream errors, provider deferral and a verified-price PASS snapshot.
- Native PostgreSQL tested SIGKILL, lease expiry, stale finish/release, lost acknowledgement, duplicates and immutable seals. The 2/5/10/20-worker runs each read three CSVs. At 20 workers this is 3 versus the #87 baseline of 60. Aggregate sampled worker RSS reached 842.5 MiB (862,712 KiB) at 20 workers. The largest single-worker peak at 300 fixtures was 164,460 KiB.
