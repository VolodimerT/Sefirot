# SEFIROT 4.1: воспроизводимый офлайн-день

Проверка проведена на сохранённых в `sefirot-core` пакетах API-Football,
доступных на 16 ноября 2026 года. Это проверка локальной структуры архива,
а не независимое удостоверение ответа провайдером. Исходные пакеты остались
в Supabase; временная копия для прогона хранится вне репозитория.

## Прогон 30 октября 2026 года

- Замороженное время: `2026-10-29T20:04:00+00:00`.
- 28 пакетов `/fixtures` с точными параметрами `date`, `league`, `season`;
  28 явно перечисленных лиг, 29 уникальных матчей. Все пакеты получены
  до первого kickoff. Полнота *всех* лиг мира не заявляется.
- 28 исходных пакетов импортированы в изолированный локальный архив с
  проверкой структуры и хешей. Повторный скан дал тот же `report_hash`:
  `dff9374b89095ae13b08e1bcdd2a72987fa9a253205806f76502ad064188c601`.
- 29/29 матчей прошли календарную проверку PREMATCH, 0 исключены; для всех
  29 отсутствуют подтверждённые предматчевые признаки и исходные
  probability seals. 203 карточки основных рынков имеют статус `PASS`;
  котировок 0, реальных решений BET 0, вызовов API 0, записей в журнал 0.
- 6 семейств малых рынков показаны как исследовательские; для ЖК остаётся
  обязательный Referee Gate. Статус экспресса:
  `NOT_EVALUABLE_NO_CERTIFIED_LEGS`.
- Проверка пригодности для TRAIN/CALIBRATION/HOLDOUT по тем же пакетам
  обнаружила 29 матчей, но `model_fit_allowed=false` и
  `INPUTS_MISSING_OR_REJECTED`: нет checkpointed source ledger,
  исходных seals и независимого удостоверения источников. Её хеш:
  `2da3f9203e089413f406cbfdeb964725d4ccb1d8eed4d861b130bae252da846e`.

Для независимого повторения нужно авторизованно выгрузить те же оригинальные
`source_packet` в JSON-массив, затем в изолированном каталоге вызвать
`archive_packets(packets, archive, frozen_at)` и запустить:

```bash
python scripts/daily_prematch_scanner.py \
  --calendar /path/to/saved-league-packets.json \
  --archive /path/to/isolated-archive \
  --day 2026-10-30 --at 2026-10-29T20:04:00+00:00 --profile MEN
```

Результат помечен `SAVED_OFFLINE_NOT_EXTERNALLY_ATTESTED`. Нельзя превращать
этот прогон в исторические прогнозы: существующий журнал не содержит
оригинальных seals и решений по этим матчам. Данные о составах, травмах,
истории команд, судьях и подтверждённых коэффициентах отсутствуют.

## Исторический replay

Исходный код PR #79 (`84dce563fc8a444118276cdaa0f332e6a8e79b8c`)
создал отдельный синтетический журнал с одним решением `PASS`. Его копия
прошла `Repository.verify()` и `Service.replay()` с `matches=true` как на
оригинальной версии, так и на этой ветке. `code_hash` остался
`542694a63cc878e58a5483ffb48c0af99f1a340c4a8a4dbd3195ffbbb3a169bb`;
SHA-256 файла журнала до и после проверки совпал. Это проверка
совместимости на синтетическом примере, а не аудит production-журнала.

## Следующие подтверждения

Для независимой калибровки нужны исходные предматчевые seals, проверенные
результаты и хронологически новые матчи TRAIN/CALIBRATION/HOLDOUT. Для
ценовой оценки нужны настоящие сопоставимые котировки, серверные receipts
и правила расчёта. До этого модельное преимущество и EV не подтверждены,
решение остаётся `PASS / stake=0`.
