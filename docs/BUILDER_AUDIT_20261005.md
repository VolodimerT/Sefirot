## Совместная вероятность голевых билдеров

`builder-grid` фиксирует 14 сочетаний из двух или трёх условий одного
матча до чтения цен. Распределение — существующий BASELINE_V1; вероятность
AND равна сумме массы общих выигрышных клеток счёта. Произведение
маргинальных вероятностей показывается только как диагностическая ошибка
предположения независимости. Отдельная совместная калибровка не выполнена.

Контракт: REGULATION_90, только push-free условия фиксированной голевой
сетки. Повторы, противоречия и логически лишние условия отклоняются.
Integer/DNB с PUSH отклоняются: пересчёт цены оставшихся условий зависит
от правил БК, которые текущий контракт не моделирует. Сочетания разных
матчей, голы + угловые/удары/карточки не поддерживаются.

Показаны шесть взаимоисключающих конечных исходов: победа хозяев сухая/
BTTS, 0:0/результативная ничья, победа гостей сухая/BTTS. Их вероятности
суммируются в единицу, а вклады успешного билдера — в его совместную
вероятность. Это конечные счёты, не модель первого гола или уровня на
60-й минуте. Проверки темпа, отсутствия атакера, судьи и пути первого
гола явно отмечены как немоделируемые.

Для каждого сочетания выполняются прежние фиксированные пробы истории:
удаление максимального target-выброса, ограничение недавних голов по P75;
плюс четыре изменения λ. Минимум вероятности и соответствующий raw
break-even — чувствительность, не доверительный интервал и не допуск.
Нехватка истории, исходные блокировки и хвост распределения видны.

```bash
python sefirot.py --db data/research.sqlite market-grid PREDICTION_ID --output data/grid.json
python sefirot.py --db data/research.sqlite builder-grid data/grid.json --output data/builders.json
python sefirot.py --db data/research.sqlite fetch-odds PREDICTION_ID --sport SPORT_KEY --event-id EVENT_ID --bookmaker BOOK_KEY --grid data/grid.json --output data/quotes.json
python sefirot.py --db data/research.sqlite compare-builder data/builders.json data/quotes.json --output data/builder-comparison.json
```

Требуются оригинальный seal текущей сборки, неизменённая сетка и
прематчевое окно. Все research outputs создаются без перезаписи; ledger
открывается read-only. Сравнение заново воспроизводит спортивный расчёт:
один пересчитанный hash изменённого отчёта недостаточен.

`compare-builder` использует только свежие API-котировки одиночных рынков,
полученные после freeze билдера, и связанную `.receipt.json`. Показывает
лучшую одиночку по raw rate-stress EV, затем raw EV; это диагностическое
ранжирование, не денежный отбор. Импорта совместной цены Builder в текущем
адаптере нет. Поэтому builder_odds/EV и сравнение «лучше одиночки» остаются
null; статус MISSING_API_BUILDER_QUOTE. Цены одиночек не перемножаются.
Локальные API receipt hashes связывают содержимое, но не являются
цифровой подписью поставщика.

## Длинная база малых рынков

`small-market-review` принимает только сохранённые API-Football пакеты
fixtures и fixtures/statistics с квитанциями. Формат:

```json
{
  "schema": "small-market-input-v1",
  "as_of": "2026-10-05T06:00:00Z",
  "fixture_id": 123,
  "team_id": 456,
  "profile": "MEN",
  "metric": "SHOTS",
  "fixture_packets": [],
  "statistic_packets": []
}
```

Массивы должны содержать настоящие полученные пакеты, включая NS целевого
матча. Пустой пример выше — схема, не готовые данные. Входы не принимают
ручные вероятности, линии или коэффициенты.

```bash
python sefirot.py small-market-review data/small-input.json --output data/small-review.json
```

| metric | Поле API |
|---|---|
| SHOTS | Total Shots |
| SOT | Shots on Goal |
| CORNERS | Corner Kicks |
| FOULS | Fouls |
| CARDS | Yellow Cards |

Соединение — по точным fixture/team ID; требуются full-time FT, одна лига,
история до cutoff и статистический запрос после наблюдения FT. Половины,
AET/PEN/LIVE, неизвестные команды, неполная пагинация и ошибки тарифа
не используются. Будущие пакеты исключаются. Null/missing не равен нулю;
дубли дают одну игру, конфликтующие counts/results/identity — карантин.
Профиль — явное утверждение оператора, не независимо подтверждённая
API-классификация всех исторических игр.

Последние три доступные игры — отдельный recent modifier. Предыдущие
10–20 — непересекающаяся long baseline; проверяются venue и удаление
крупнейшего всплеска. Recent mean описательно сжимается к long mean с
весом recent_n/(long_n+recent_n), без подбора по исходам этого аудита.
Показана отдельная статистика следующего соперника: что другие команды
набирали против него; отсутствие второй команды или достаточной базы
сохраняет блокировку. Сила оппозиции ещё не скорректирована.

Эти mean/counts не превращаются в вероятность линии или EV. Распределение
малых рынков, совместная модель с голами, price adapter и prospective
калибровка пока отсутствуют. Даже полная база остаётся D/stake=0.
Карточки требуют отдельного Referee Gate; фолы его не закрывают.
