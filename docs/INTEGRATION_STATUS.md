# CORE 2.1 — внешние данные и база

## 1. Котировки

Выполнено: адаптер The Odds API v4 для **одного заранее выбранного матча и одной полной линии 1X2**. `odds-events` ищет точное совпадение матча после спортивного `capture`. `fetch-odds` принимает единственный ID события/ключ букмекера, получает h2h и сохраняет `quotes.json` и отдельную квитанцию. Действия не загружают новостей, не меняют вероятность и не исполняют ставки. Требуется подтверждение правил расчёта за 90 минут.

Реальный HTTP-вызов с пользовательским ключом ещё не выполнен: в среде нет `SEFIROT_ODDS_API_KEY`. Транспорт, ошибки и формат ответа протестированы офлайн. Источник не гарантирует доступность цены в вашем аккаунте и не содержит Parimatch 24 в опубликованном перечне букмекеров. Сверка с вашей доступной линией обязательна. Храните заполненные файлы в `data/`, которая исключена из Git.

Официальная документация: https://the-odds-api.com/liveapi/guides/v4/ ; букмекеры: https://the-odds-api.com/sports-odds-data/bookmaker-apis.html .

## 2. Supabase

С согласия пользователя создан проект Supabase `sefirot-core` (`kxqpwgwihtjmqlcxgfxp`, регион `eu-central-1`, стоимость создания $0/месяц). Две миграции развернули 22 таблицы локального журнала, внешние ключи, индексы, RLS без открытых политик и запрет UPDATE/DELETE. Проверка SQL в реальном Postgres: 22 таблицы, 22 триггера, 9 дополнительных индексов внешних ключей, ни у `anon`, ни у `authenticated`, ни у `service_role` нет SELECT или USAGE на приватной схеме. Данные и ключи не загружались. Подробности и замечания линтера — в `SUPABASE_DEPLOYMENT_REPORT.md`.

`schema/supabase_core.sql` соответствует итоговой схеме и предназначен для **новых** баз. У этого проекта история из двух миграций; повторно выполнять файл в нём нельзя. Синхронизации с SQLite пока нет: приложение продолжает работать локально, а Supabase пока является пустой частной базой. Серверный ключ в приложение или репозиторий не помещается.

Документация защиты доступа: https://supabase.com/docs/guides/api/securing-your-api ; изменение автоматического доступа к таблицам: https://supabase.com/changelog/45329-breaking-change-tables-not-exposed-to-data-and-graphql-api-automatically .

## 3. Исследовательская модель

Новая модель на невиденных реальных матчах не проверена. Архивная P0 диагностика остаётся отрицательной: 312 решений дали −9,70% при ожидаемом моделью положительном EV. Нельзя открывать денежный допуск из-за появления нового источника коэффициентов. Классы и BET/PASS остаются исследовательскими, пока не появится новый проспективный holdout и подтверждённые цены исполнения.

## 4. Исключения текущей работы

Tavily исключён по прямому запросу пользователя. Его коннектор при одной попытке до уточнения вернул `UNAUTHORIZED`; интеграции нет. Запрос текста Supabase `changelog.md` через веб-поиск вернул ошибку типа содержимого; актуальный changelog и страницы безопасности сверены через официальные HTML-страницы и поиск документации Supabase. Подготовленная загрузка архива P0 ранее дала HTTP 500; сохранение альтернативным способом прошло. Эти ошибки не изменили денежные ворота CORE.
