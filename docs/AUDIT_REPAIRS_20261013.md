# Исправления подтверждённых ошибок основной ветки

База: `d09a8af22f0dec8c84bc203d468b913b46fc2f94`, CORE 2.3.0.
Исправления предназначены для отдельного PR. Основная ветка и рабочие базы
не изменялись; запросы к платным API не выполнялись.

## Что исправлено

1. Результат `FINISHED` для обычного футбольного матча нельзя принять раньше
   90 минут от начала. Это консервативный нижний предел, а не подтверждение
   фактического завершения. Проверка работает до записи результата, расчёта
   ставок и статистики. Та же проверка применяется к входной истории.
   Ранний `VOID` остаётся допустимым при корректной хронологии.
2. Проверка SQLite и подготовка облачного снимка сверяют служебные даты,
   идентификаторы и связи с каноническим содержимым записи. Эквивалентные
   часовые пояса принимаются. Повреждённый JSON и ссылки дают отказ.
   SQLite дополнительно проверяет физическую целостность и внешние ключи.
3. Проверка квитанции задания, действие, квитанция и событие журнала
   выполняются в одной транзакции. Вложенные операции используют savepoint.
   Сбой откатывает все изменения; два исполнителя не выполняют задание дважды.
4. CLI `verify` возвращает код 2 при `integrity=false`, код 0 при успешной
   проверке. Формат JSON с результатом проверки сохраняется.
5. Загрузка и проверка `--policy` включены в общий обработчик ошибок CLI:
   ошибочный файл возвращает JSON с `ERROR`/`PASS` и код 2 вместо traceback.

Схема данных и старые записи не переписываются. Некорректные существующие
метаданные теперь приводят к отказу проверки. Изменение исходников меняет
`code_hash`; для воспроизведения старого решения требуется исходная сборка,
как и предусматривал контракт проекта. Старые разрешения не переносятся
на изменённую сборку.

## Проверки

- Исходные 191 тест проходят после исправлений.
- Добавлены 13 регрессионных тестов, в том числе проверки преждевременного
  результата, служебных полей, отказа квитанции/журнала и двух исполнителей.
- Добавлены четыре проверки на настоящем PostgreSQL: повторная выгрузка,
  откат частичных вставок, конфликты и права ролей. Они включаются только
  для новой локальной базы `sefirot_sync_test`; удалённые адреса и параметры
  переопределения запрещены. Отдельный CI job создаёт одноразовый PostgreSQL 16.
- Локально: 205 выполненных тестов прошли, четыре PostgreSQL-теста пропущены
  из-за отсутствия доступной изолированной базы. Общее число: 209.
- Полная локальная проверка релиза проходит: demo с целостностью и replay,
  синтетический backtest и ретроспективные регрессии.
- CI запускает тесты и полную проверку релиза на Ubuntu/Windows,
  Python 3.11/3.13, а также отдельную проверку PostgreSQL.

Математическая модель и правила денежного допуска специально не менялись.
Проверка результатов не доказывает прибыльность и не обращается к рабочим API.
Статус удалённого CI публикуется в PR после проверки конкретного коммита.
