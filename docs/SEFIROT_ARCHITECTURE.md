# Архитектура SEFIROT CORE 2.0

## Инварианты Конституции

F1–F8 сохранены. Спортивные сведения не содержат цен. `capture` сначала проверяет происхождение и время, рассчитывает сценарий и распределение, сохраняет весь прогноз в транзакции. `decide` отдельно получает цены после времени seal. Новая цена не корректирует вероятность. Новый спортивный факт создаёт ревизию с причиной и родителем.

Никакой рейтинг, высокий EV, ручное утверждение калибровки или успешный синтетический тест не снимает критическое возражение. Допуск возможен только при отсутствии блокировок, пригодной калибровке, подтверждённой истории нужного контекста, пройденном holdout, свежей перепроверке, одобренной версии политики и положительном разрешённом риске. Автоматического исполнения нет.

## Состав и границы

Девять сефир — функции одного детерминированного приложения. Общая инфраструктура: `contracts.py`, `repository.py`, `service.py`. Оркестратор не голосует. Версии определяются хешем исходников, политики и calibrator artifact. Любая смена кода требует повторной регистрации модели. Для старого решения replay требует исходную версию кода.

Хранилище SQLite включает 11 исходно запрошенных сущностей и служебные таблицы решений, пересмотров, split assignments, калибраторов, holdout, маршрутов моделей и постматчевого аудита. Все строки дополнительно защищены от UPDATE/DELETE триггерами. Hash-chain связывает журнал и содержимое прогнозов/решений/результатов. Это защита от ошибок и выявление повреждений, а не внешняя нотариальная фиксация.

## Вероятность и математические границы

Модель футбольных голов использует прошлые результаты той же лиги, известные к `as_of`, экспоненциальное уменьшение веса старых игр, отдельные атаки/защиты команд и домашнее преимущество из истории лиги. Слабые выборки стягиваются к prior. Предположение независимых Пуассонов прозрачно указано. Остаток распределения за пределом счёта 35 оценивается; слишком большой остаток блокирует допуск.

Сценарий содержит обоснования, составы, контекст и наиболее вероятные счёты. Тактика не получает выдуманный численный коэффициент: неподтверждённое соответствие блокирует допуск. Количественная модель тактических взаимодействий остаётся исследовательским ограничением.

Сначала оценивается заранее закрытый пул: максимум семь кандидатов, по одному на основное семейство. Калибровка — замороженные reliability bins WIN/PUSH/LOSS с интервалами Wilson; диапазон расширяется чувствительностью к темпу голов. Это не гарантия покрытия истинной вероятности конкретного матча. Отдельный holdout должен оценить обобщение.

EV = p(win) × (odds − 1) − p(loss). Fair odds = (1 − p(push)) / p(win). Edge = p(win) − (1 − p(push))/odds. Границы EV находятся по допустимой области трёх вероятностей с суммой 1; нельзя одновременно использовать несовместимые экстремумы. Маржа вычисляется только для полной одновременной 1X2 линии одного букмекера.

## Пересчёт, конфликты и остановка

Источники объединяются по independence_group. Подтверждение перепечаткой не считается независимым. Противоречащие действующие факты блокируют анализ. Источник может явно заменить свою более раннюю запись; чужой источник не может её «перезаписать». Новые факты вызывают новый sports snapshot. Сервис отклоняет неизменные данные и превышение бюджета ревизий. Цикла ожидания между сефирами нет: каждый запуск конечен и заканчивается BET/PASS либо ошибкой с PASS.

Неизвестность: мало истории, новый/изменённый тренер, ротация, объявленная новизна, недопустимый формат, неизвестный контекст компетенции, необъяснённое движение линии. Программа сама обнаруживает эти признаки во входных данных; она не узнаёт новости без поставщика. Политика текущей версии консервативно блокирует такой контекст.

## Рейтинги и деградация

Метрики группируются по лиге, конкретному рынку, сценарию и версии модели. Каждая сефира имеет отдельную историю доказанных ошибок, оценку с Wilson-интервалом и число уникальных матчей. WIN/LOSS не становится автоматической оценкой правильности сефиры. Нет голосования или среднего рейтинга, отменяющего veto.

Контроль качества вероятностей сравнивает нормированный multiclass Brier с заранее фиксированной базовой оценкой. Два последовательных ухудшившихся окна либо повторные критические ошибки замораживают контекст. Возврат требует записи исправления и прошедшей проверки на прогнозах, созданных после заморозки. Пороговые числа — исследовательская политика, не эмпирически доказанные универсальные константы.

Версии сравниваются на общих матчах/рынках. Уверенное ухудшение даёт ROLLBACK; команда применения переключает активный calibrator на ранее валидированную версию. Если изменился код, требуется восстановить соответствующую архивную сборку — загрузка несовпадающего кода запрещена.
