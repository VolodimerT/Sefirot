# Простой локальный режим Сефирота

Один запуск для готовых локальных заданий:

```powershell
py -3 sefirot.py --db data/offline.sqlite work inbox --text
```

Режим читает JSON-задания из папки, сохраняет исходный прогноз и решение,
показывает короткую русскую карточку. Он не запрашивает API и не размещает
ставки. `--watch` повторяет обработку каждые пять секунд; обычный запуск
обрабатывает папку один раз. Повтор не создаёт второй прогноз или решение.
Код завершения 2 означает ошибку задания/журнала, 0 — обработку без ошибок.
Обработанная карточка PASS тоже является успешной обработкой.

## 1. Сначала прогноз

Файл `inbox/01-capture.json`: поля `id`, `type="CAPTURE"`, `payload.sports`.
В `sports` помещается полный уже проверенный sports-only JSON по
[INPUT_CONTRACT.md](INPUT_CONTRACT.md). ID задания выбирается один раз,
например `match-123-capture`. Пул `markets` можно опустить: используются
семь прежних основных контрактов, один на семейство. Они не расширяются
автоматически до сетки 50 или Builder.

Запустите `work`. Вывод сообщает, что прогноз зафиксирован до цены.
Исследовательский или синтетический прогноз не становится денежным допуском.
Без пригодных спортивных данных нельзя собрать реальный прогноз из текста
или картинки: это интерфейс обработки данных, не их источник.

## 2. Затем цена и перепроверка

После seal добавьте `inbox/02-decide.json`. Поля задания:

```json
{
  "id": "match-123-decision",
  "type": "DECIDE",
  "payload": {
    "prediction_job_id": "match-123-capture",
    "quotes": [],
    "recheck": {"checked_at": "2026-10-06T20:00:00+00:00", "evidence": []},
    "portfolio": {"bankroll": 1000, "peak": 1000}
  }
}
```

Это пример формы с отсутствующими ценами/фактами, не готовая ставка.
В реальном задании нужны исходные quotes и настоящая перепроверка со
своими timestamps. Примерную дату не переносить в реальные данные.
`prediction_job_id` связывает решение с заданием CAPTURE: копировать
длинный prediction hash больше не нужно. Прежний `prediction_id` также
поддержан; одновременно задавать оба нельзя.

Снова запустите ту же команду. Она покажет сохранённую карточку: вероятность,
цену, EV/stress, ограничения и вердикт. Отсутствующие цены не подставляются,
timestamps не обновляются задним числом. Более поздний факт требует новой
ревизии прогноза по прежним правилам capture, а не смены содержимого задания
с уже использованным ID. Для новой проверки цены нужен новый decision job ID.

Файлы читаются по имени. Сначала завершите CAPTURE, затем открывайте цену;
имена `01-capture.json`, `02-decide.json` сохраняют этот порядок. Цены,
полученные до нового seal, нельзя выдавать за полученные после него.

## 3. Результат и аудит

После матча добавьте задание `RESULT` с исходным result payload. `CLOSING`
принимает `match_id` и исходный quote с phase CLOSE. Result/closing не
разрешают новые прематчевые решения после kickoff. Все временные и
идентификационные проверки остаются в Service.

Действие, receipt задания и аудит коммитятся вместе. При сбое receipt
откатываются и результат действия, и промежуточные записи. Сохранённые
receipt новых заданий привязаны к hash-chain; подмена останавливает очередь.
Изменение задания при том же ID вызывает ошибку. Старые jobs и receipts
не переписываются; их прежняя область доказательства сохраняется.

Просмотр `report`, `accounting`, `replay`, `compare` без rollback открывает
только существующий журнал read-only. `backtest` работает без журнала.
Указание несуществующей БД при просмотре больше не создаёт пустой файл.

Для проверки установки: `py -3 sefirot.py demo --text`. Demo целиком
синтетический. Реальная эффективность оценивается исходными будущими
прогнозами с результатами, а не количеством успешных программных тестов.

Обычная справка по-прежнему содержит 10 команд; `work` доступна в ней.
`api-health` и остальные низкоуровневые команды сохранены для явного
вызова и в `--labs --help`. Legacy, LIVE, догон и execution не включены.
