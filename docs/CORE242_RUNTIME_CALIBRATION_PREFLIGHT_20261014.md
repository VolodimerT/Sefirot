# CORE 2.4.2: работающий runtime и безопасная будущая калибровка

Продолжение единого кандидата `5cd6c680b10f742f89aedffcf321beb992b4dc16`,
черновик PR #56. Проверки ниже выполнены 14.10.2026 только чтением

не вызывались, секреты не читались, реальная калибровка не запускалась.

## Подтверждённые ошибки и исправление

`scripts/calibration_fit_gate.py` проверял журнал в отдельном снимке,
а затем читал таблицы в autocommit. Другой процесс мог дописать журнал между
этими чтениями. Повторная проверка перед `Service.calibrate` тоже не удерживала
резервирование записи: другой процесс мог изменить входы перед fit.
Итоговый отчёт использовал числа первого, уже устаревшего preflight.

Три контрпримера упали на исходном коде. Первые два используют настоящие
раздельные SQLite-соединения на одноразовой базе; assessment и создание
calibrator замещены синтетическими функциями, реального fit нет.

Исправление сохраняет один read-only `BEGIN` от проверки журнала до конца
assessment. Явный `--fit` держит существующую `Repository.transaction()`
с `BEGIN IMMEDIATE` от свежей проверки до создания исходного артефакта;
вложенная транзакция Service использует прежний savepoint. Отчёт берёт
свежие входы, SQLite lock/error даёт понятный CLI exit 2 без повторов.
Все 15 профильных тестов проходят. Полный release и CI фиксируются на
точном опубликованном коммите в PR #56.

Изменены только script, его tests и документация/инструкции. Все
`src/sefirot`, семь MODEL_MODULES, Policy, протокол независимой калибровки,
старые источники, seals и reports сохранены. CORE code/model/policy hashes
остаются прежними. Это защита будущего запуска, а не разрешение real fit.

## Проверяемый порядок следующего operational этапа

1. Отдельное разрешение владельца на изменения production. До любых provider
   calls сверить все 25 service IDs и deployed commits с приватным перечнем.
   Старые сканеры/boot-fetch consumers остановить. Отдельно решить судьбу v2
   MCP-сервиса: его остановка прервёт текущий chat worker. Не терять durable
   checkpoint revision 59 и существующую очередь, не пересоздавать БД.
2. Для сохранённого MCP endpoint подготовить отдельно разрешённый переход
   на точный проверенный candidate commit. Сохранить прежнюю авторизацию
   без чтения/изменения секретов; проверять сначала только запретные пути
   при PAUSED budget. Не выполнять pending `sports_probe` при старте.
3. Только после подтверждения лицензии/аккаунта/доступной квоты и отдельного
   разрешения API: один ограниченный status probe через общий gateway,
   явное UTC approval окно <=15 минут, одна разрешённая попытка и запас.
   Сохранить оригинальную квитанцию. Переход на другие ключи/прямой API,
   повторные запросы и автоматическое продление запрещены.
4. Получить подлинный полный league/season schedule и отдельную проверку
   букмекерских quote/settlement. Назначить новые будущие fixtures/UTC окна
   до capture. Недоступные поля остаются null, исторические прогнозы
   не превращаются в новую независимую выборку.
5. Собирать CALIBRATION с оригинальными квитанциями и всеми пропусками
   в знаменателе. После достаточных данных и отдельного разрешения fit
   заморозить calibrator. Затем назначить новый независимый HOLDOUT,
   не пересекающийся с TRAIN/fit_ids, без подбора по его результатам.

При rollback сначала оставить сбор остановленным и budget PAUSED,
сохранить checkpoint/attempts и возвратить только точный прежний runtime
после отдельного решения. Не запускать старый незащищённый collector.
