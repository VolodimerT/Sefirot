# Проверка независимости выборок перед калибровкой

В проверенном кандидате `538e62505b0d9f1c9dde5a66fc891b211ef208fa` команда
`scripts/calibration_fit_gate.py` проверяла записи CAL, но не использовала
проверку всех выборок из `calibration_quality_audit.py`. На изолированных
данных с 60 проверяемыми записями она возвращала `fit_ready=true` при повторе
fixture в TRAIN/CAL, TRAIN после CAL, неизвестной роли TEST и пересечении
HOLDOUT с исходными fit_ids. Существующий аудитор эти случаи отвергал.

Теперь обе проверки перед возможным fit используют общий `cohort_errors`
для всех исходных планов и замороженных калибраторов в одной транзакции.
Ошибки перечисляются в отчёте и блокируют fit. Корректный отдельный TRAIN
перед CAL сохраняет прежнее поведение. Прямой запуск скрипта и импорт
модулем используют одну проверку.

Регрессии используют собственные синтетические данные и подменяют проверку
прогноза для изоляции проверки выборок. Это не реальные 60 матчей и не
проверка доступа к API. Настоящий fit, сбор данных и HOLDOUT не выполнялись.
Математика CORE, Policy, протокол, прогнозы, решения и старые отчёты сохранены.

Проверка оригинальной базы остаётся read-only:

```sh
python scripts/calibration_fit_gate.py --db /private/existing-original.sqlite --output /private/new-preflight.json
```

Отсутствующие реальные источники, лига, сезон, зарегистрированные выборки
и независимый HOLDOUT остаются блокерами. `fit_ready` означает только
результат проверки исследовательских данных, а не разрешение на реальные
операции или ставки. **PASS, ставка 0.** Render rollout отложен владельцем.
