# Накопление данных, сессия и аудит билетов — обновление 04.10.2026

Три новые функции поверх расширения main markets: наблюдаемый API-архив,
проверка группы существующих прогнозов до цены и сверка фактических одиночных
билетов с записанным решением. BASELINE_V1/STRICT и денежные правила не изменены.
Обновление опубликовано в `feature/data-session-audit-20261004`, черновик PR #9
к `core242-version-audit`. На `c4d5fcf` все 343 теста и полный demo прошли
на Windows/Ubuntu с Python 3.11/3.13. Доступ GitHub connector к записи
в `Sefirot` восстановлен установкой приложения на аккаунт владельца.
Денежного допуска нет; результат CI проверять на последнем коммите.

## 1. Архив доступных спортивных наблюдений

```powershell
py -3 sefirot.py football-fetch --endpoint fixtures --param date=2026-10-04 --param timezone=Europe/Kyiv --output data/day.json
py -3 sefirot.py football-archive data/day.json --directory data/sports-archive
py -3 sefirot.py football-from-archive --directory data/sports-archive --fixture-id ID --profile LOWER --source-reliability 0.8 --output data/sports.json
```

Первый шаг делает один явно запрошенный HTTP-запрос. Два следующих работают
с уже полученными пакетами без сети, ключей и расходования квоты. Дата, профиль
лиги и надёжность источника задаются оператором; 0.8 — пример утверждения,
а не измеренная надёжность API. Команда не определяет MEN/WOMEN/RESERVE/LOWER
по названию лиги и не заполняет неизвестные составы, травмы, тренера или тактику.

Архив проверяет host, endpoint, HTTP, ошибки внутри ответа, количество строк,
полную пагинацию, идентичность матчей, хронологию и payload_hash. Секретные
параметры запроса запрещены. Новые пакеты получают имена по hash; повтор не
перезаписывает наблюдение. FT берётся из score.fulltime. AET/PEN, отменённые,
незавершённые и чужие соревнования не дополняют выборку.

История объединяется по fixture ID. Повторные снимки не создают новые матчи;
received_at результата остаётся временем первого настоящего FT-наблюдения.
На заданном cutoff более поздние пакеты не используются. Позднее исправление
счёта, несовместимая идентичность или одновременные противоречащие наблюдения
изолируют матч. Текущий таргет никогда не становится собственной историей.
Названия таргет-команд связываются с историей по точным API team ID; совпадение
имени при другом ID не считается подтверждением команды.

Выходы: sports.json, sports.json.receipt.json и sports.json.coverage.json.
Последний показывает допустимую выборку по каждой команде, сколько игр ещё
не хватает, причины исключения и конкретные блоки спортивных данных.
history_coverage_ready не означает полноценную готовность: составы и контекст
проверяются отдельно. Даже SPORTS_DATA_GATES_PASSED не заменяет калибровку,
holdout, текущую цену и финальное решение.

Архив позволяет постепенно копить доступные результаты. Он не восстанавливает
прошлый сезон, которого нет в источнике, не обходит тариф и не объявляет старые
данные свежей формой. Автоматическое расписание не создаётся. Локальный hash
не является подписью провайдера: удаление пакетов или согласованная полная
подделка всех метаданных не обнаруживаются.

## 2. Групповая проверка прогнозов

```powershell
py -3 sefirot.py --db data/sefirot.sqlite session --text --output data/session.json
py -3 sefirot.py --db data/sefirot.sqlite session --prediction-id ID1 --prediction-id ID2 --text
```

По умолчанию показан последний известный seal каждого ещё не начавшегося
матча. Закрытые прематчи не вытесняют будущие матчи за limit; при явных ID они
остаются доступными с PREMATCH_CLOSED. BUILD_MISMATCH не переподписывается.
Сводка считает блоки по матчам, а не семь раз по семи рынкам, и перечисляет ID,
для которых имеет смысл следующий запрос цены. Показывается усечение списка.

Перед чтением проверяется целостность журнала. Команда не создаёт ledger,
прогноз, котировку, решение или ставку. Старая спортивная snapshot не становится
новой проверкой состава. READY_FOR_PRICE_RECHECK не является разрешением BET.

## 3. Аудит одиночных билетов

```powershell
py -3 sefirot.py ticket-audit examples/ops_ticket_audit.json --output data/ticket-audit.json
py -3 sefirot.py --db data/sefirot.sqlite ticket-audit data/tickets.json --link-ledger --output data/linked-audit.json
```

Вход ticket-audit-input-v1 обязательно содержит статус REPORTED_UNVERIFIED,
описание источника, единую валюту и timezone. Каждый билет содержит id,
match_id, day, odds, stake, outcome и ровно один market либо reported_market.
Допустимы WIN/PUSH/LOSS/VOID/PENDING. Заявленные данные не являются официальным
settlement и не импортируются в денежный журнал. IDs матчей должны быть
согласованы источником: программа не угадывает, что разные IDs означают один матч.

market — известный основной контракт. Если из аудита неясно, была команда
хозяином или гостем, сохраняется непреобразованный reported_market; HOME/AWAY
не выдумывается. Его accounting доступен, а проверка контрактного соответствия
и вложенных линий отмечается как непроверяемая. Невозможный PUSH для известного
полулинейного/беспушевого контракта отклоняется.

Аудит считает оборот, возврат, P/L и ROI с точными денежными расчётами. Pending
не считается проигрышем и не входит в знаменатель реализованного ROI; VOID
и PUSH возвращают stake. Повторный match_id становится одним event cluster.
Разные линии одного семейства и стороны показываются как вложенный тезис.
Шесть разных матчей не объявляются шестью статистически независимыми идеями.

При --link-ledger исходный журнал открыт только для чтения и проверяется.
Сверяются BET, точный матч, выбранный рынок, лимит ставки, БК, цена, момент
решения и прематч-время входа. Суммарный stake всех билетов с одним decision_id
не может считаться допустимым, если он превышает записанный лимит, даже когда
каждая часть меньше лимита. Изменённая цена требует нового decide; старое
решение не переписывается. Неполные времена/неизвестный БК остаются неопределёнными.

Поле reported_decision не является доказательством BET. reported_flags
отделены от подтверждённых записанным журналом блоков. WIN/LOSS не назначают
MODEL_MISS или качество value. Наличие starting_bankroll включает только
диагностическое сравнение с текущими экспериментальными turnover caps;
параллельный открытый риск и движения банка не реконструируются.

Дни входов считаются в указанной IANA timezone с учётом DST. Для Windows
нужна база tzdata; обычный pip install . устанавливает закреплённую версию.
Основание: [Python zoneinfo](https://docs.python.org/3/library/zoneinfo.html).
Ключи и личные билеты в репозиторий не помещать; пример полностью синтетический.

## Совместимость и проверка

Все три функции имеют monetary_permission=false и execution_enabled=false.
Новых экспрессов, small markets или LIVE нет. Вероятностные модули не менялись:
model_hash сохраняется; code_hash новой сборки отличается. Старые seals,
approvals и денежные разрешения не мигрируют автоматически.

Регрессии: tests/test_operations_upgrade.py. Полный локальный release gate —
python scripts/verify_release.py. Проверки не доказывают доходность. Реальные
наблюдения, техническое demo и контролируемые unit fixtures различаются;
synthetic admission fixture не является реальной модельной валидацией.
