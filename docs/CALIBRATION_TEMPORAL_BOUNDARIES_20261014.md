# Временные границы калибровки

На head `1eb49eeb2c60bc83e9b15f099d7e19b67eb85cc7` подтверждены два пробела:
при 60 допустимых записях из 75 плановых матчей fit_ready становился true,
хотя оставшиеся 15 матчей CAL ещё не начались; аудитор также не отвергал
fit, созданный до матчей из его исходных fit_ids. Локальная подпись такого
артефакта сама по себе не доказывает правильный порядок событий.

Проверка перед fit теперь передаёт явную UTC-отсечку в общий cohort_errors.
Пока последний kickoff объявленного CAL-плана не прошёл, ошибка
CALIBRATION_WINDOW_NOT_CLOSED блокирует fit. Равенство отсечке тоже отказ.
Достигнутые 80% coverage не позволяют завершить ещё будущую выборку раньше.
Когда плановая временная граница пройдена, прежние проверки исходных FT
результатов, минимальной выборки и coverage остаются обязательными. Пропуски
не удаляются из знаменателя; календарная дата не заменяет доказательство FT.

Для замороженного fit проверяется весь объявленный CAL-план, содержащий
использованный fit_id, а не только удачно полученная часть этого плана.
FIT_NOT_AFTER_DECLARED_CALIBRATION_WINDOW отвергает fit до или одновременно
с этой границей. Связь вычисляется после чтения всех планов, поэтому порядок
записей ничего не меняет. Более поздний несвязанный CAL-план не переписывает
старый fit. Обычный read-only аудит ещё будущего плана без готового fit остаётся
инвентаризацией; он не объявляет корректный prospective сбор испорченным.

Регрессии используют свои синтетические записи, без API и реального обучения.
CORE, Policy, protocol, прежние прогнозы и решения не изменяются. Отсутствие
источников, CAL/HOLDOUT и доказанного преимущества сохраняет PASS и ставку 0.
Протокол независимой калибровки остаётся DRAFT_NOT_REGISTERED. Render отложен.
