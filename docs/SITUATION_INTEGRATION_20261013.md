## Поведение

Строгий запрос связывает fixture/status/kickoff/observation, source ID/revision,
receipt hash, model identity, intent/depth и время запроса. Сервер читает
исходную квитанцию по её ID, проверяет hash, подпись сборщика и совпадение
параметров. Клиент не передаёт путь, пакет источника или право на ставку.

Подпись сборщика удостоверяет сборщика. Происхождение спортивного статуса
требует отдельной внешней проверки; UNATTESTED_ARCHIVE всегда получает HOLD.
Явно разрешённые синтетические квитанции используются для инженерных тестов.
Запоздалый NS, старое LIVE-наблюдение, неизвестный статус, противоречие
времени или отсутствие источника дают HOLD. FT до 90 минут по времени
исходного наблюдения также получает HOLD. AET/PEN не завершают результат CORE.

CLI, POST /v1/situation, MCP sefirot_situation и situation job используют один
диспетчер. Он не открывает/восстанавливает SQLite и не вызывает CORE.
Ответ содержит режим, источник, время, причину и следующее действие.
Все шесть разрешений остаются false, реальная проверка источника — false.
Вероятности и цены диспетчер не рассчитывает. Просмотр альтернативных рынков
остаётся отдельным исследовательским модулем и не подключён к этим API.

## Проверки

- 77 тестов situation/router/SQL transport, включая 5 новых Python-регрессий.
- PostgreSQL WASM (PGlite 0.5.8): 18 SQL-групп и 12 relay-групп.
- Сквозной локальный HTTP → relay → PostgreSQL → Python worker → restart:
  только claim/source/complete; прежние SQLite-байты и seals/replay сохранены.
- Отдельная свежая PostgreSQL 16.15: 18 проверок identity/time/permissions,
  lease/idempotency и ролей. Для RPC — только service_role; прямой доступ
  к частному registry закрыт, RLS включён, search_path пустой.
- Полный локальный release: 1282 теста, 1278 passed + 4 PostgreSQL skips.
  Эти четыре проверки выполнены отдельно; mirror — 5/5 без пропусков,
  shared budget — 10/10, в том числе 16 конкурентных запросов.
- Demo integrity/replay=true; синтетический backtest 12 матчей / 84 рынка,
  audit 49 случаев. Это технические проверки; точность модели не измерена.

Матрица Ubuntu/Windows × Python 3.11/3.13 и PostgreSQL mirror/budget проверяются
на опубликованном head; окончательные статусы и ссылки находятся в draft PR.
Node.js 22 и npm ci с закреплённой зависимостью добавлены в CI и README.

Синтетический warm HTTP benchmark: 100 вызовов для каждого из пяти режимов,
p95 7,559–44,319 мс на общем хосте во время других проверок. Время не включает
сеть поставщика, очередь, расчёт CORE или холодный старт. Полный production
SLO и ускорение по отношению к другому окружению этим измерением не доказаны.
