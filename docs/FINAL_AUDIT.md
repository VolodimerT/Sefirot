# Итоговая проверка архитектуры и кода CORE 2.0

## Кто проверял

Проведена отдельная самопроверка исходников, негативных сценариев и соответствия Foundation. Внешний независимый аудитор не привлекался; его заключение не заявляется. Тестовая проверка выполняется повторяемым `scripts/verify_release.py`. Точное число тестов и итог последнего прогона приведены в `reports/TEST_OUTPUT.txt`; добавлены проверки исследовательского контура из нового cross-audit.

## Найдено и исправлено в этой работе

1. **Безусловный PASS в старом ядре.** Новый Арбитр имеет настоящие ветки playable / conditional / skip / unplayable и BET/PASS. Положительный допуск проверен контролируемыми тестами всех gates.
2. **Готовые флаги вместо доказательств.** Новый вход содержит сами факты, source IDs, независимые группы, три времени, составы и ссылки. Пользовательская галочка calibration_validated не принимается.
3. **Неполная воспроизводимость.** Сохраняется весь вход и контекст принятия решения, включая тогдашние результаты компетенции и портфель. Replay не читает будущую историю.
4. **Любой проигрышный счёт ошибочно блокировал рынок.** Теперь counterexample сохраняется, а death-test ищет потерю основания/отрицательный EV при спортивном стрессе.
5. **Границы EV могли сочетать несовместимые вероятности.** Экстремумы берутся только на simplex WIN/PUSH/LOSS с суммой 1.
6. **Повторный выбор рынков обходил закрытый пул.** Пул фиксируется для всего матча и всех ревизий.
7. **Повтор исполнения старого решения обходил текущую экспозицию.** Проверка актуального состояния и лимитов выполняется в транзакции записи исполнения; повтор ID идемпотентен.
8. **История одного матча могла многократно улучшать/ухудшать рейтинг.** Ролевой рейтинг и число грубых ошибок учитывают уникальные матчи.
9. **Заморозка автоматически исчезала после хорошей серии.** Состояние сохраняется до явного исправления и нового прошедшего holdout; старые данные не могут служить восстановлением.
10. **Маржа считалась по неполному набору котировок.** Overround доступен только для полной 1X2 линии одинаковых времени, БК и line_id.
11. **Старую котировку можно было сделать свежей новым временем получения.** Возраст считается по observed_at.
12. **Результат не запускал постматчевый аудит.** `result` атомарно создаёт metrics и предварительный отчёт с UNDETERMINED/UNKNOWN; ручной доказанный разбор дописывается отдельно.
13. **Хеш версии не включал расчёт выплат из старого пакета.** Новый пакет самодостаточен; его полный исходный код включён в code_hash.

## Архитектурные риски и остаточные ограничения

| Риск | Сдерживание | Что остаётся |
|---|---|---|
| Дублирование сефир | Девять обязанностей, единый процесс, владельцы описаны в карте | Старое ядро сохранено для совместимости, основной вход явно `sefirot.py` |
| Избыток власти Арбитра | Не может менять вероятность, снимать veto или переписывать журнал | Администратор локального компьютера технически контролирует исходники и БД |
| Цикл/взаимная блокировка | Конечный pipeline, ограниченные ревизии, прежний snapshot не пересчитывается | Новые данные требуют поставщика; программа не выдумывает их |
| Критическая ошибка скрыта рейтингом | Critical veto сильнее рейтинга, роль/контекст могут замораживаться | Метки качества и независимости исходных источников заявлены поставщиком |
| Утечка будущего | Три времени, source chronology, target ID, fit/test disjoint, captured context | Локальные часы и вручную проставленные метки можно сфальсифицировать |
| Переобучение | Closed pool, fixed policy, held-out periods, baseline comparison | Многократный выбор лучшей лиги/версии извне всё ещё требует исследовательской дисциплины |
| Ложная уверенность | Невалидированные интервалы явно обозначены; synthetic не сертифицирует | Wilson оценивает частоту в группе, а не истинную вероятность конкретного матча |
| Модель голов | Прозрачный prior/decay, sensitivity, tail bound | Независимый Poisson не описывает все зависимости голов/составов/состояний игры |
| Пороговые значения | Отдельная исследовательская конфигурация; её approval не отменяет holdout | Default risk/monitoring thresholds не проверены на реальных данных |
| Причинность постматчевого разбора | UNKNOWN разрешён; результат отдельно от качества | Одна ошибка не устанавливает истинную причину, нужен внешний анализ |
| Надёжность БД | Транзакции, FK, immutable triggers, связанный hash-chain | Нет внешнего timestamp/witness, backup пользователь должен хранить отдельно |
| Автономность | Команды и локальный inbox/watch автоматизируют цикл без LLM | Нет сетевого провайдера составов, истории и odds |
| Исполнение | Никакого подключения к букмекеру; только журнал ручного действия | Фактические ставки вне системы могут нарушать её решение |

## Критерий приёмки

Программная сборка должна проходить тесты, demo, replay, integrity и backtest. Это выполнено в указанной в отчёте среде. Денежная модель дополнительно требует реального проспективного holdout и одобренной версии политики. В поставке такого доказательства нет, поэтому реальная денежная готовность **не заявляется**.

## Дополнение после cross-audit

Проверены 1900 реальных матчей; 380 финальных тестовых исходов не использовались для выбора гиперпараметров/температуры. Результат отрицателен для гипотезы преимущества: подробности в CROSS_AUDIT_RESPONSE.md. Денежная готовность не установлена. Обнаружен риск ложной уверенности от положительного среднего CLV при отрицательной доходности; оба показателя опубликованы вместе. Недостоверные исторические receipt timestamps не подставлялись.

Блок benchmark имеет намеренно отдельный статус EXPERIMENTAL и не импортируется как сертифицированная модель. Он не заменяет основную вероятностную модель семи рынков без её собственной проверки. Покрытие истинной индивидуальной вероятности не оценивается по одному бинарному результату; отчёт возвращает null. Прежний параметр `kelly_fraction` в конфигурации сохранён для совместимости, текущий риск его не использует.

Текущий gate CORE использует нейтральный baseline соответствующего WIN/PUSH/LOSS рынка. Это недостаточно для вывода о превосходстве над профессиональной линией. Отдельный реальный benchmark прямо показывает эту слабость; не следует вручную одобрять денежную политику до внешней проверки модели и более сильных сопоставимых baseline. Система умеет вычислять условия допуска, но наличие механизма допуска не доказывает обоснованность исследовательских порогов.
