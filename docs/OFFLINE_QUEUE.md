# Рабочая очередь в браузере, 08.10.2026

Откройте Сефирот одной командой на компьютере с Python:

```powershell
py -3 sefirot.py --db data/offline.sqlite work inbox --web
```

Linux/macOS: `python3` вместо `py -3`. Оставьте команду работающей,
откройте напечатанный адрес `http://127.0.0.1:8765/` в браузере этого
компьютера. Для другого свободного порта добавьте `--port 0`: смотрите
фактически напечатанный адрес. Остановка сервера — Ctrl+C.

На странице видны имена файлов, последние 30 сохранённых заданий,
карточки с объяснением решения и ошибки последнего ручного запуска.
Время показано по Киеву. «Обновить обзор» только перечитывает журнал;
«Обработать очередь» запускает прежний `process_inbox` на тех же файлах.
Просмотр не создаёт журнал или папку и не читает содержимое ожидающих
JSON-файлов. Пустая очередь не создаёт журнал даже при ручном запуске.

## Ежедневный порядок

1. Добавьте `01-capture.json` со спортивными данными без цены.
2. Нажмите «Обработать очередь»: CAPTURE должен успешно сохранить seal.
3. После seal добавьте `02-decide.json` с новой ценой и реальными
   свежими фактами, используя `prediction_job_id` исходного CAPTURE.
4. Нажмите кнопку снова и прочитайте вердикт и объяснение.
5. После матча добавьте RESULT и CLOSING, обработайте и сохраните аудит.

Формат JSON и временные правила: [OFFLINE_WORKFLOW.md](OFFLINE_WORKFLOW.md).
Имена файлов управляют существующим порядком обработки, а не браузер.
Полученную до seal цену нельзя выдать за полученную после него.
Повторный запуск использует прежний receipt; изменённый job с тем же
ID вызывает ошибку. Actions/receipts/audit сохраняют атомарность worker.
Статус обработки DONE не означает BET: записанный PASS — нормальный итог.

Карточка показывает **сохранённое** решение, а не текущую цену, состав
или новый денежный допуск. Для новой цены/фактов нужен новый DECIDE job;
изменение спортивной гипотезы требует нового seal по прежним правилам.
Архивная сборка не пересчитывается автоматически текущим интерфейсом.
Рейтинги A/B/C/D/RED, calibration/holdout/data gates и модель сохранены.

## Область работы

Это локальный экран существующего CLI/Service, без внешних web-зависимостей.
Он слушает только 127.0.0.1 и работает на компьютере, где запущен CLI.
Для телефона/удалённого доступа отдельный интерфейс ещё потребуется.
API, auto bet, LIVE, watch и новый расчётный runtime не добавлены.
`--web` несовместим с `--watch`/`--text`; обычные способы `work` сохранены.
Обычных команд по-прежнему десять. Входы остаются подготовленными JSON:
формы создания спортивных данных/загрузки фотографий ещё нет.

GET читает существующую БД в одной read-only SQLite snapshot и заново
проверяет hash-chain/content bindings. При ошибке карточки скрыты, запуск
заблокирован. Future receipts не добавляются в более ранний обзор.
Last-run ошибки живут в памяти сервера; DONE receipts и исходные решения
остаются в журнале. Большой журнал проверяется целиком, не по cached OK.

POST требует exact loopback Host, same Origin и session token; body
ограничен 512 байт, чужие пути/методы не запускают worker. HTML escaping,
no-store и CSP исключают внешние ресурсы и скрипты. Referrer-Policy
same-origin сохраняет Origin обычной локальной формы; no-referrer
сделал бы его null по [Fetch Standard](https://fetch.spec.whatwg.org/#append-a-request-origin-header).
Эта защита не предназначена для многопользовательского public hosting.

## Проверка

18 новых тестов с реальными HTTP-запросами к временному loopback серверу:
ручной POST, read-only GET, session/origin/Host guards, body limits,
escape, future cutoff, changed/tampered records, quote-after-durable-seal,
безопасный повтор, ERROR отдельно от PASS, совместимость CLI flags.
Существующие offline workflow/stability tests также проверены.
Полный release и актуальный code_hash: reports/RELEASE_CHECK.json;
удалённый CI сверять на exact published head.

Headless Chromium в этой среде отсутствует: реальный браузерный click/layout
не проверялся. HTTP lifecycle подтверждён, форма сверена со стандартом.
[Синтетический статический образец](../examples/offline_queue_preview.html)
показывает ту же разметку без обработки, данных пользователя и secret token.
Он не является работающей очередью или примером пригодной ставки.
