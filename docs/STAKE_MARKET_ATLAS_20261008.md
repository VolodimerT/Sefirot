# Stake Market Atlas — SEFIROT, 08.10.2026

## Результат и граница достоверности
Добавлен независимый **lossless-каталог реально наблюдавшихся рынков Stake**:
`scripts/stake_market_atlas.py`. Он не заменяет существующие
`src/sefirot/stake_provider.py` и `stake_mapper.py`, а дополняет их.

- Принимает сохранённые **оригинальные Stake snapshot JSON** (хэш и время),
  оставляет **все полученные raw-рынки и исходы**, включая неизвестные,
  заблокированные или неподдерживаемые core-системой.
- Сохраняет группы, шаблоны, названия, specifiers, lines, outcomes, Stake IDs,
  цены, флаги активности и привязку к fixture/snapshot. Ничего не додумывает.
- Разметка `MAIN_REFERENCE_ONLY / SMALL_REFERENCE_ONLY / UNMAPPED_RAW`
  показывает сопоставимость с текущим mapper, **не верификацию расчёта БК**.
- Наличие названия "Yellow Cards" или "Fouls" — только подсказка.
  Фолы и ЖК разделены; Referee Gate, YC/game и YC/foul не подтверждены.
- Ни одного нового рынка НЕ разрешает для `engine.decide`, не создаёт
  прогнозов, не изменяет `Policy`/MODEL_MODULES, не пишет в SQLite,
  не создаёт ставки. Всегда `stake=0`, `monetary_permission=false`.
- Поддерживает футбольные **прематчевые** запросы с реальным sealed
  prediction. Нет live, догонов, автоматической торговли или экспрессов.

## Что является «всеми рынками»
**Все рынки, реально возвращённые конкретным API-ответом, сохраняются,
включая неизвестные.** Это **не** обещание всех рынков букмекерской платформы.

Текущий экспериментальный GraphQL-запрос Stake:
`templates(includeEmpty:false,limit:50)`, `markets(limit:50)`
без подтверждённой пагинации. Полученный ответ может быть усечён.
Атлас **всегда** отмечает `completeness_proven=false` и проверяет
наличие 50 рынков в одной группе/шаблоне, а также отсутствующих групп.
Отсутствие этих индикаторов не доказывает полноту API.

Источник sports API — web GraphQL интерфейс Stake, не стабильная
официальная букмекерская API-спецификация; поля и правила могут меняться.
Документация публичной API Stake покрывает другие семейства эндпоинтов.
При HTTP 403/смене схемы — прекратить сбор, не обходить защиту.

## Использование
1. Создать **оригинальный** прематчевый sealed prediction через
   существующий `capture` / `work`, экспортировать его в файл без
   изменения `id`, `sports`, `sealed_at`.
2. Настроить действующий `STAKE_API_TOKEN` в **существующем
   credential/Vault-пути SEFIROT**; не класть его в JSON, Git или чат.
3. Из корня репозитория (Python >= 3.11):

```bash
# Только одно точное предматчевое событие; если event отсутствует
# в ограниченном списке upcoming, возвращает PASS.
python scripts/stake_market_atlas.py harvest \
  --prediction data/prediction.json \
  --output data/stake_match_snapshot.json \
  --atlas data/stake_match_atlas.json

# Добавить реальные сохранённые снапшоты других матчей в общий каталог.
python scripts/stake_market_atlas.py build \
  data/stake_match_snapshot.json data/stake_second_snapshot.json \
  --output data/stake_global_atlas.json

# Без сети, на уже сохранённых исходных Stake файлах:
python scripts/stake_market_atlas.py build data/stake_match_snapshot.json \
  --output data/stake_atlas.json

python -m unittest discover -s tests -p test_stake_market_atlas.py -v
```

`harvest` ищет только UPCOMING soccer, требует точное совпадение
двух команд и kickoff со sports seal, проверяет `captured_prematch`,
`reconstructed=false`, хэш JSON. Обращение к ценам идёт после seal
и до kickoff. Максимум 200 событий в discovery, 500 групп у одного
матча; запросы порциями по восемь групп. Эти пределы защищают от
неограниченного сканирования, **но НЕ доказывают полноту данных**.
При неизвестном исходе, отсутствии exact match или лимитах — PASS.

Все пути вывода должны быть новыми; существующие файлы не перезаписываются.
Для общего каталога снимков одной и той же игры в разные моменты требуется
отдельная версия time-series, текущий build отклонит дубликат, чтобы не
выдать два снимка одной игры за независимые fixture-наблюдения.

## Следующая доработка после реальных ответов
1. Получить несколько подлинных предматчевых снимков, проверить группы,
   шаблоны, specifiers и покрытие без API-креденшалов в отчёте.
2. Уточнить стабильную пагинацию у поставщика. Пока такой контракт не
   проверен, НЕ заявлять `all markets fetched`.
3. Для каждого `UNMAPPED_RAW` сделать таблицу точных, тестируемых
   вариантов (line, period, team/player, WIN/PUSH/LOSS, правило расчёта).
4. Сначала main markets: 1X2, DC, DNB, форы, тоталы, BTTS, ИТ.
   По quarters/Asian splits — только после реализации правил half win/loss.
5. Потом small: CORNERS, FOULS, SHOTS, SOT; cards — только через Referee Gate
   с подтверждённым судьёй, YC/game, YC/foul и правилами расчёта БК.
6. Только после отдельной калибровки, результатов и prospective holdout
   рассматривать монетарный допуск. Отсутствие модели => PASS.

## Тесты и честный статус
Unit tests используют **синтетические примеры и mock-провайдер**.
Живой токен Stake недоступен в среде разработки; подлинных новых ответов
Stake этот коммит не получил. Поэтому число реально доступных рынков,
полнота и цены сегодня **не установлены**.
