## What the diagnostic actually does

1. Requires `forward-scorecard-v1` JSON with untouched local hash and
   research-only flags. Rejects altered totals, invented scored fixtures,
   duplicate markets, missing candidate rows, future kickoffs and impossible PUSH.
2. Separately reports **planned/scored/missing** fixture coverage. Seven
   candidate markets of one game are correlated observations, not independent
   matches.
3. Exact-market/profile diagnostics: Brier (half sum of squared 3-way errors),
   multiclass clipped log loss, macro ECE (10 bins), and **paired base-minus-raw**
   deltas on the exact same fixtures. **Negative** delta Brier/log loss means
   the frozen calibrated forecast scored better than the raw forecast.
   No conclusion when missing observations.
4. Canonical raw-WIN fit-bin occupancy by exact contract/profile. A bin with
   20 samples is **only population-ready**, not calibrated by this script.
   Unseen bins are unknown, not reported as adequately populated.
5. Optional exploratory 95% bootstrap interval only with at least 30 scored
   **distinct fixtures spanning eight UTC dates**; resamples dates and averages
   market deltas **within each fixture** to avoid pretending same-match legs
   are independent. Fixed seed, purely descriptive, no certification.
6. Marks CALIBRATION metrics as in-sample training audit, never independent
   proof. For HOLDOUT, requires a frozen calibrator, at least 60 scored
   distinct fixtures and >=80% coverage **only for a descriptive review
   readiness label**. The real `Service.validate` still requires per-context
   independent proof, fresh order, policy gates, plus any stronger predeclared
   accuracy protocol.
7. Never fits a model, changes training parameters, queries APIs, approves
   deployment, imports bookmaker prices, or authorizes money. Always
   `monetary_permission=false`, `stake=0`.

## Run locally with actual original scorecards

From project root, with a populated local database and a genuine forward plan:

    python sefirot.py --db data/research.sqlite forward-scorecard ORIGINAL_PLAN_ID --output data/scorecard.json --text
    python scripts/calibration_quality_audit.py data/scorecard.json --output data/calibration_quality.json
    python -m unittest discover -s tests -p test_calibration_quality_audit.py -v

Input must be unmodified, source-backed and generated by the existing
`forward-scorecard` command. The audit output path must be new.
Never backfill excluded matches, override results, or assign roles after kickoff.

## How to ACTUALLY calibrate the probability model safely

1. Restore reliable historic API-Football results/competition profiles and
   prospective sports snapshots first. Current REAL capture rate remains the
   major bottleneck. An account-level provider 403 must be handled via
   authorized account recovery, not bypassed.
2. Before any kickoff, reserve **all** fixtures and assign CALIBRATION/
   HOLDOUT separately. Persist real source receipts and as-of time.
3. Collect enough independent, settled, original CALIBRATION predictions
   for the **exact original market+line+profile+WIN bin**. Inspect missing
   bins with this read-only diagnostic. One fixture counts at most once per
   contract, and only suitable data may be used.
4. Fit an actual frozen calibrator through existing `Service.calibrate`
   ONLY on already-reserved CALIBRATION observations with the matching
   code/model/Policy identity. Fitting itself is not approval.
5. Reserve a completely new HOLDOUT forward cohort with this frozen
   calibrator, then collect results without selection bias. Compare raw vs
   frozen base on the same fixture, market and date. Do NOT revise thresholds
   after seeing HOLDOUT results.
6. Run canonical `Service.validate` (per-context min_holdout and probability
   gates). If it fails, retain KEEP_SHADOW and use a NEW future cohort for
   any changed model. No release based on TRAIN/CALIBRATION or previously
   opened TEST data.
7. If new markets (corners, cards, combined Bet Builders) are required,
   they need **separate source-backed models, settlement contracts and
   holdout**. Do not apply football-goal calibration to independent props.

## Limitations

A scorecard hash proves internal local consistency, **not provider-signed
provenance**; the original scorecard job/receipt and sealed ledger must
be verified separately. Bootstrap confidence is exploratory. ECE alone
does not prove quality or profitability. The historical 380-match
audit describes retrospective, already-viewed comparisons. There are
currently zero independently validated, fresh probability improvements
available for deployment.

The correct status of any synthetic fixture, empty scorecard or absent
real forward data is **NO SCORABLE FORECASTS / KEEP_SHADOW**.
