# Выбор версии прогноза в операторском отчёте

Проверено на базе unified draft PR #56, коммит
`8bed823be7d740f8af8c335687a96de82ac867ff`. Render отложен владельцем.

Подтверждены две ошибки среднего приоритета (P2) в read-only
`research.prematch_readiness.operator_report`:

- Выбор `prediction_id` ограничивал readiness, но решения и карточки
  отбирались по матчу. Разные исходные версии одного матча смешивались;
  новая версия без решения показывала старое решение и старую карточку.
- Явно переданный пустой идентификатор отключал фильтр и возвращал весь
  журнал вместо отказа. Только `None` обозначает отчёт без выбора версии.

Решения и связанные карточки теперь отбираются по исходному `prediction_id`
решения. В выбранной версии остаются все её решения до временной отсечки.
Если решения ещё нет, массивы решений и карточек пусты. Отчёт без выбора
версии продолжает показывать архив разных версий. Отсечка, проверка оригиналов,
архивный статус и отсутствие подтверждённых свежих котировок сохранены.
Невалидный или ещё не существующий на отсечке идентификатор возвращает
прежний закрытый статус `UNREADABLE_OR_UNVERIFIABLE` с пустыми массивами.

Пять новых регрессионных методов используют только собственную синтетическую
SQLite БД и настоящие capture/revision/decide. До исправления — шесть
assertion failures; после исправления проверяются разделение версий,
несколько решений одной версии, отсутствие решения, временная отсечка,
пустой выбор и сохранение общего архива. Каждое чтение запрещает socket I/O
и сверяет исходные SQLite bytes. Синтетические решения остаются PASS/0.

Изменение не меняет CORE, Policy, модель, исходные seals/decisions, протокол
калибровки или исторические отчёты. Оно не подтверждает реальные API,
источники, CAL/HOLDOUT или преимущество модели. Реальный сбор/fit, paid API,
секреты, deployment, production и main не затрагиваются. PASS, ставка 0.

Полный release выполняется в отдельной копии дерева, чтобы не перезаписать
исторические tracked reports. Точный опубликованный SHA, результаты полного
локального release и CI фиксируются в отдельном отчёте этапа.
