# Архивные fixture-ID: чтение без изменения оригиналов

## Подтверждённая ошибка

На кандидате `9330e755607bb5c4315094cbce1b41a7db4aad9b` операторский отчёт
возвращал UNREADABLE_OR_UNVERIFIABLE и пустые списки при одном fixture-ID,
не подходящем к строгому chat-answer-v1. В проверенной закрытой копии
оригинального snapshot: 31 прогноз, 27 решений, 62 audit events; три решения
имеют неподдерживаемый fixture-ID. Из-за них исчезали остальные 24 решения
и весь список readiness, хотя целостность SQLite/журнала была подтверждена.

## Исправление

Контракт `schema/chat_answer_v1.json` и `research/chat_answer_contract.py`
не меняются. ID не нормализуются и не заменяются. Только два точных отказа
STRING_PATTERN/STRING_BOUNDS для $.fixture_id создают отдельную недоступную
ссылку на исходные decision_id/forecast_seal_id после повторного `_record`.
В ней нет CORE PASS/BET, вероятности, EV, котировки или сырого fixture-ID.
Все прочие ошибки verifier, SQL, хэшей или временных связей по-прежнему
закрывают отчёт полностью и очищают также недоступные ссылки.

`ledger_status` сообщает о проверке оригинального локального журнала, а
`archive_view_status` — о возможности его отображения: COMPLETE, PARTIAL,
UNAVAILABLE; до проверки NOT_CHECKED. `unavailable_original_decisions`
содержит максимум последние 100 ссылок, как и существующие списки решений.
Явные prediction_id и cutoff применяются до подготовки всех видов записей.
Неподдерживаемое решение другой ревизии или после cutoff не попадает в отчёт.

Панель показывает предупреждение и ссылки на недоступный оригинал отдельно
от прошедших строгую проверку карточек. При потере сессии они очищаются вместе
со всеми частными данными. Это не новый архивный формат ответа или перенос
данных: пользователь видит причину неполного отображения, а оригиналы остаются
в прежнем snapshot и приватном inventory.

## Доказательства и ограничения

До исправления шесть новых регрессий воспроизвели отказ. Проверяются смешанный
архив, длинный ID, выбор ревизии, временная отсечка, повреждение журнала и
неожиданная ошибка verifier после частично собранного отчёта. Существующий
Node DOM smoke дополнен тремя группами: смешанные записи, только недоступные,
очистка. Существующий session smoke проверяет удаление новых ссылок при 401,
403, 503 и опоздавших ответах. На исходном коде сохранились строгие отказы
chat-answer-v1 для неподдерживаемого ID.

После исправления закрытая оригинальная копия даёт 31 readiness, 24 проверенных
решения/market views, три недоступные ссылки и 62 audit events. Raw SQLite
SHA-256 до и после равен
`3ae7ad31957eebba32ef9d337a07cc335f79c95144112fb2502df42a48581ba2`.
В Git и публичный отчёт входят только агрегаты, не ledger или построчные IDs.
Это подтверждает чтение сохранённого архива, не происхождение provider input,
текущий runtime или доступ к свежим котировкам.

Все src, SQL, worker/relay, Policy/model и калибровочный протокол сохранены.
stake_snapshot остаётся запрещённым в unified SAFE_KINDS: официальный доступ
и его отдельный контракт не подтверждены. Hosted SQL, production rollout,
платные API, сбор данных, real fit и HOLDOUT здесь не выполняются.
RESEARCH_ONLY / PASS / stake=0.

Точный опубликованный SHA, полный release и 20 CI jobs фиксируются в итоговом
отчёте после выполнения. Проверки приложения не заменяют Android smoke в
реальной разрешённой среде или отдельное разрешение на deployment.

## Подтверждённый сетевой отказ CI

Первый коммит `3fdf440a9b8478087ccbdc0a8ac8aea09e143ce9` получил
ECONNRESET в PR Ubuntu/Python 3.14.3 на npm ci (run 38804421828,
job 116661460010, exit 152). Тесты этой задачи не запускались; setup-python
успешно установил точную 3.14.3. Это отказ загрузки тестовой зависимости,
не падение приложения. Failed SHA и лог сохраняются, повтор не скрывается.

В workflow добавлены npm cache по package-lock.json, prefer-offline и явные
fetch-retries=3 / factor=2 / timeout=60000ms с паузами 1000..10000ms;
весь install step ограничен пятью минутами. Это максимум три повтора
скачивания публичной pinned тестовой зависимости, не повторы provider API.
npm ci по-прежнему проверяет lock/integrity; версия PGlite 0.5.8, TLS,
ignore-scripts/no-audit/no-fund сохранены. Cache хранит npm content cache,
не node_modules. При исчерпании лимита job остаётся failed; ошибок тестов
или установки не игнорируем. Новое дерево проходит отдельный полный CI.
