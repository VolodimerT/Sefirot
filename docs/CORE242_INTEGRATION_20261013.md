## Как разрешены конфликты

Конфликты были в восьми файлах: workflow, backtesting, CLI, contracts,
evidence, repository, service и worker.

| Область | Решение |
| --- | --- |
| Временная проверка результатов | Сохранён общий `result_chronology` из #51: FINISHED для REGULATION_90 раньше 90 минут запрещён в service, history, backtest и адаптерах; ранний VOID остаётся допустимым без feedback. |
| Worker | Сохранены расширенные задания, именованные ссылки и атомарная запись действия вместе с квитанцией из #51; регрессии отката и повторного запуска из #52 проходят. |
| CLI | Сохранена версия #51: ошибки policy попадают в обработчик, verify повреждённого журнала завершается с кодом 2. |
| Repository | Сохранены read-only режим, savepoint, откат неудачного commit, индексированные выборки и ограниченный cache из #51. Добавлена сверка SQL ID, времени и ссылок с payload из #52 для всех таблиц. |
| Cloud mirror | Перед выгрузкой проверяются метаданные и канонические байты; повреждённые строки отбрасываются до облачной записи. |
| CI | Сохранены Node 22 и четыре сочетания Ubuntu/Windows × Python 3.11/3.13, добавлена отдельная реальная проверка PostgreSQL mirror. Workflow общего бюджета PostgreSQL из #51 сохранён. |

Локальная проверка допускает прежнее эквивалентное форматирование JSON;
облачный snapshot по-прежнему требует канонические сохранённые байты.
Сверка метаданных выполняется заново даже при прогретом cache и неизменном
payload. Число SQL-запросов не зависит от числа записей: один проход по журналу
и один по каждой таблице, без отдельного SELECT для каждого события.

Два теста старого стека ожидали, что SQL-время останется незаметным для
`Repository.verify()`. Теперь они требуют отказа. Risk audit возвращает
`JOURNAL_INVALID` до расчёта контекстов. В синтетическую model fixture добавлено
реальное поле `registered_at`; исходные проверки ticket audit сохранены.
Добавлен контрпример изменения только SQL-времени второй SQLite-сессией при
прогретом cache. Проверка query-count усилена сравнением малого и большого журнала.
