# SEFIROT CORE 2.4.2: оптимизация 03.10.2026

В существующей рабочей ветке ускорены повторный захват прогноза, расчёт исходов,
проверка неизменных записей и обработка результатов. Добавлена проверка готовности
до запроса коэффициентов. Версия остаётся 2.4.2, PR #8 продолжается; новый релизный
номер и новая модель не создаются. main остаётся 2.3 до независимой проверки.

## Что изменено

1. Точный повтор capture сравнивает match, спортивный snapshot, пул, полный fit,
   ID калибратора, текущую сборку и политику; возвращает исходный seal.
   Изменённый факт или пул проходит прежние проверки и требует ревизии.
2. Прогнозы выбираются по индексированному match_id; чужие прогнозы не
   декодируются ради одного матча. Решения результата выбираются по prediction_id.
3. Семь контекстов settlement получают один набор feedback, событий здоровья
   и postmortem в общей транзакции вместо семи полных чтений.
4. Кешируются только правила WIN/PUSH/LOSS для неизменного рынка и сетки счёта:
   до 64 сеток, до 4096 счетов каждая. Значения вероятностей, цены и разрешения
   не кешируются; bool/float/отрицательные счета и плохие массы проверяются каждый раз.
5. Все 22 таблицы и 44 immutable-trigger создаются одним атомарным commit.
   Foreign keys включены до BEGIN; частичная ошибка откатывает весь bootstrap.
6. Проверка целостности заново читает байты каждой связанной записи и проверяет
   полную audit chain и охват записей. Кешируется только canonical digest по
   свежему SHA256 байтов, максимум 4096 identities без хранения полных payload.
   Изменения другой SQLite-сессии, новые неподписанные записи и смена JSON-формата
   проверены отдельно. journal_ok и денежные разрешения не кешируются.

## Практический порядок работы

После capture, до просьбы найти новые коэффициенты:

```powershell
py -3 sefirot.py --db data/sefirot.sqlite readiness ID --text
```

| Статус | Следующее действие |
|---|---|
| BLOCKED_BEFORE_PRICE | Закрыть перечисленные пробелы модели или спортивных данных. Коэффициент их не закрывает. |
| READY_FOR_PRICE_RECHECK | Собрать свежую цену и настоящую финальную перепроверку, затем decide. |
| BUILD_MISMATCH | Открыть исходный seal его архивной сборкой и политикой. |
| PREMATCH_CLOSED | Записать результат и аудит; новые прематч-решения не создавать. |

readiness — read-only вид существующего seal. Он не вызывает API, не вычисляет
новые вероятности, не пишет решение и не выдаёт ставку. Возраст фактов остаётся
исходным; старый snapshot не объявляется свежей перепроверкой. Финальные price,
реальная экспозиция и risk проверяются при обычном decide/execution.

## Проверки и совместимость

- 297 тестов проходят; release gate 7.663 сек в локальной среде.
- Demo, replay, integrity; 12 синтетических матчей / 84 рынка и 49
  ретроспективных settlement-cases сохранены.
- 68 рыночных контрактов на четырёх перестановках сетки: 272 точных
  сравнения с исходным накоплением вероятностей.
- Хеш всех семи векторов вероятностей и стрессов до/после совпадает:
  `8db25c895b23c687572c9bfe972b1241836545c88c3e6d4f7455c68322101c37`.
- Полный context_hash и результат/health settlement совпадают для журналов
  0, 200 и 1000 дополнительных матчей. Identities сборок исключены из
  статистического сравнения; они закономерно различаются.
- BASELINE_V1/STRICT, policy и Конституция сохраняются. Числа известного
  исторического TEST не использовались для выбора порогов.

База: опубликованный `ed4dcc17c0227a1a1992e2c032101e3affb47d70`,
архивный тег v2.4.2; локальный исходный tree точно совпадал с опубликованным.
Текущая рабочая ветка: core242-version-audit. Старый тег и исходный ZIP
сохраняются для архивного replay; свежая поставка помечена OPTIMIZED_2026-10-03.

Новый code_hash: `49fbf90cc34c53dfaddf052f7fe1000095913d45a9963ed9b3758355ad04905d`.
Новый model_hash: `46f1c991a2ee93a2d68a0ae9c1b091b866660501980f52c2456a83bf96ba6617`.
Математика совпадает на проверенных данных, но исходник _payoffs.py изменён:
model_hash закономерно новый. Старые fitted-артефакты, seals и approvals
не переподписываются и автоматически совместимыми не объявляются.

Воспроизведение: исходный архивный тег распаковать отдельно; путь к нему
передать через --source-root. Оба запуска использовать с одним текущим
скриптом и одинаковым Python:

```text
python scripts/benchmark_runtime.py --source-root ../SEFIROT_CORE_2_4_2 --output data/runtime-before.json
python scripts/benchmark_runtime.py --output data/runtime-after.json
```

Это измеренная техническая оптимизация. Прогнозное преимущество, ROI и
прибыльность не подтверждены; будущая независимая проверка остаётся нужна.
