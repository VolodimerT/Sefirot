# Открытые вопросы и исследовательские ограничения

## Зафиксированные решения

- Доступный локальный продукт работает через JSON и SQLite. Внешние провайдеры и Supabase не нужны для запуска.
- Численные defaults выделены в версионированную экспериментальную политику. Это позволяет тестировать систему без молчаливого объявления исследовательских идей утверждёнными правилами.
- D1/D2 остаются закрыты. Поддерживаются только футбол, основное время, целые/половинные линии; остальные правила отклоняются.
- Monetary gate требует отдельного утверждения версии политики и проверенного несинтетического holdout; пользовательская галочка «модель валидна» не принимается.

## Напряжения требований и выбранные явные механизмы

| Требования | Механизм |
|---|---|
| F1 независимость от линии / F6 необычное движение | Вероятность заморожена; движение меняет допуск, новый спортивный факт создаёт новый seal |
| P2 сценарий раньше рынка / нужна спецификация исхода | До цены фиксируется максимум семь исходов, по одному на семейство |
| F2 допуск до риска / нулевой риск | Предварительный допуск, затем риск; ноль превращает окончательный итог в PASS |
| F3 невиденный тест / постоянная обратная связь | Назначения CALIBRATION/HOLDOUT/MONITOR фиксируются до прогнозов; тестовые матчи не попадают в fit того же калибратора |
| P4 пересчёт / P5 независимость Оппонента | Оппонент выдаёт причину; новая ревизия создаётся владельцем модели, предел попыток конечный |
| P7 поздние entry/closing / неизменяемое решение | Отдельные добавляемые записи; исходное решение не изменяется |
| P15 ручная коррекция / воспроизводимость | Закрытый перечень причин, родительский ID, новая версия и сохранённое старое решение |
| Условный допуск / критический пробел | Условия только некритические, риск снижен; критический пробел всегда PASS |

## Что ещё нужно подтвердить эмпирически

1. Независимый реальный набор матчей, источники с доказуемой хронологией и заранее замороженные тестовые периоды.
2. Калибровка и покрытие вероятностных диапазонов по конкретной лиге и рынку; reliability-bin интервалы не равны гарантии точности отдельного матча.
3. Адекватность Пуассона, домашнего преимущества и влияния состава/тактики. Текущий код проверяет тактическое основание, но не обучает коэффициенты влияния игроков.
4. Пороги просадки, риска, допуска, freshness, размера выборки и мониторинга. В поставке они экспериментальные и не активированы для денежного допуска.
5. Надёжность объявлений провайдера о независимости источников. Локальная программа не может доказать, что две публикации не являются перепечатками.
6. Независимая внешняя фиксация времени/hash и внешний аудит модели. Самопроверка кода не заменяет их.
7. Данные зависимости матчей/рынков для количественной корреляции. Сейчас общие факторы ограничивают риск консервативными лимитами, а не выдуманной корреляционной матрицей.
8. Поддержка исправленных официальных результатов, переносов и специальных settlement terms: пока отдельные исправления результата блокируются, VOID поддержан.

Ни один из этих вопросов не означает разрешение менять Конституцию F1–F8 или объявлять производственную валидность на основании синтетических тестов.

## После аудитов 27–30 сентября, CORE 2.3

Полная карта реализации и конфликтов: [AUDIT_UPGRADE_20260930.md](AUDIT_UPGRADE_20260930.md). Открыты:

1. Категоричные MODEL_MISS/BAD_PASS из аудита 30 сентября против предостережения WIN≠value в Foundation и аудитах 27–29. По умолчанию это гипотезы, автоматическое качество UNDETERMINED; для доказанной категории нужен содержательный внешний review.
2. Снятие stress<0 veto и новые reduced/very-small stake caps. Классы готовятся диагностически; нужен новый holdout с заранее выбранной политикой. Tamworth/Taunton не доказывают превосходство менее строгого допуска.
3. Пересекающиеся MEN/WOMEN/RESERVE/LOWER: требуется схема population × competition_tier. Текущий первичный enum не должен использоваться как автоматическая классификация.
4. Отдельные fitted league priors, home/away splits, overdispersion, H2H modifier, player/GK impact и тренировочный SoS. Текущий trace и вероятностные пороги не заменяют этих моделей.
5. Sharp-market consensus: сейчас полная линия одного БК либо явно одиночный break-even proxy, без заявления sharp consensus.
6. Критерий «близкий EV» для выбора защищённой целой линии. Предпочтение нельзя молча добавить по результату уже известного матча или расширять закрытый pool после просмотра odds.
7. Исходные seal, receipts, entry/closing для 49 аудитных случаев отсутствуют. Их можно проверять как settlement/contract regressions, нельзя ретроспективно объявить невиденным доказательством модели.
