# SEFIROT CORE v0.7 — локальный аналитический помощник

**Статус: теневой исследовательский прототип.** Работает автономно на Python 3.11+ без интернета и API-ключей. Это небольшая расчётная программа с иллюстративной Elo-моделью, а не обученная нейросеть или доказанный источник прибыли. Денежное решение всегда **PASS**; программа не размещает ставки.

## Запуск за минуту на Windows

1. Установите Python 3.11+ с официального сайта и отметьте добавление Python в PATH.
2. Скачайте архив проекта, распакуйте его и откройте папку `Sefirot-main` (в ней лежит `START_SEFIROT.bat`).
3. Дважды щёлкните `START_SEFIROT.bat`. Откроется **вымышленный** пример расчёта. Никаких пакетов устанавливать не нужно.

Для проверки кода дважды щёлкните `TEST_SEFIROT.bat`. При запуске из PowerShell сначала перейдите в папку проекта, где лежат `tests` и `test_sefirot.py`:

```powershell
py -3 test_sefirot.py
```

Для анализа своего матча подготовьте JSON-файл истории по примеру `examples/history_sample.json`. Каждый результат должен иметь документированные `kickoff`, `result_received_at`, счёт и источник. В PowerShell запустите (замените значения на подлинные данные, время с часовым поясом и **новый** путь журнала):

```powershell
py -3 run_sefirot.py analyze --match-id match_001 --kickoff 2099-10-01T19:00:00+03:00 --home "Team A" --away "Team B" --source "synthetic-example" --published-at 2026-09-20T12:00:00+03:00 --history examples/history_sample.json --journal data/match_001.jsonl --confirmed
```

Дата 2099 года, команды и история в примере вымышлены и служат только для знакомства с программой. Флаг `--confirmed` — **ваше** заявление о проверке источника, не автоматическая проверка. Если его убрать, программа сохранит `ASSUMPTION` и завершит работу с PASS. Если история достаточна, она покажет вероятность 1/X/2 **до того**, как спросит название букмекера и три коэффициента. Потом покажет implied P, модельную P, EV, маржу и PASS. Все записи одного матча сохраняются локально в `data/*.jsonl`; папка исключена из Git. Для повторного анализа нужен новый `match-id` и отдельный файл журнала.

Если история малочисленна или время неверно, расчёт останавливается с PASS. Время получения исторических результатов указывается вручную и пока не подтверждается автоматически. Ручной ввод составов, tactical fit, public trap, Referee Gate, независимая калибровка и остальные рынки не реализованы. Ни LIVE, ни догон, ни экспрессы не запускаются. Основные рынки кроме 1X2 и малые рынки ещё не доступны.

## Что находится внутри

- `run_sefirot.py` и `START_SEFIROT.bat`: запуск и пошаговый анализ 1X2; `TEST_SEFIROT.bat` и `test_sefirot.py`: запуск тестов.
- `src/sefirot_core`: чистые расчёты, Elo-пример, временные барьеры, локальный журнал, аудит и теневой backtest.
- `tests`: 43 автоматических теста; `examples`: вымышленные данные; `docs/AUDIT_INTEGRATION.md`: сопоставление исторических аудитов и правил.
- `pyproject.toml`: метаданные проекта; `.gitignore`: локальные журналы и секреты не попадают в репозиторий.

Ниже приведены детали и ограничения исследовательского ядра.

Проверяет временные барьеры и независимый расчёт 1X2 на истории матчей. Включена **иллюстративная Elo-модель** с ручными параметрами и явно **некалиброванными** диапазонами Low/Base/High. Это не проверенная прогнозная модель, не полноценный SEFIROT и не разрешение ставить деньги. Никаких внешних сервисов или зависимостей.

## Запуск

Из каталога проекта (`Sefirot-main` при скачивании архива GitHub):

```powershell
py -3 test_sefirot.py
py -3 examples/demo.py
```

Для Python 3.11+; на Windows 3.13 тоже работает. Запуск тестов не требует установки пакетов. Исходники в `src`, тесты в `tests`, параметры в `config`. Демонстрация содержит исключительно вымышленные матчи. В этом прототипе денежная ставка всегда имеет решение `PASS`.

Обозначения: коэффициенты десятичные, вероятность в долях, `EV = p * odds - 1` применима только к бинарной выплате без возврата. Для трёх исходов 1X2 подсчитывается маржа всего трёхстороннего рынка одного букмекера. Модель использует лишь исторические результаты, полученные до `as_of`, и требует минимум три прошлых матча на каждую команду (техническое правило прототипа, не утверждённый порог допуска). Elo, домашнее преимущество, базовая частота ничьих и ширина диапазона заданы эвристически, не обучены на реальных данных. Веса сценария, контекст и качество источников ещё не реализованы. Исходы DNB и азиатские форы здесь отсутствуют. Хеш seal обеспечивает повторяемость байтов снимка, **не является защищённым неизменяемым журналом**.

`HistoricalMatch` требует времени получения результата. При backtest нельзя заполнять это поле задним числом моментом окончания матча без доказательства происхождения. Будущие и поздно полученные результаты автоматически исключаются из оценки; число исключённых хранится в результате. Некалиброванный диапазон **не** является доверительным интервалом и не свидетельствует о положительном EV в реальной игре.

`walk_forward_1x2` умеет посчитать multiclass Brier на запечатанных до матча `SportsOnlySnapshot` и позже полученных результатах. Он **не восстанавливает** исторические снимки из финальных данных. Если таких подлинных снимков нет, backtest на реальных матчах проводить нельзя. Демонстрация и тесты используют вымышленные матчи и не служат доказательством качества модели.

Процессные правила аудита встроены в `audit.py` и исследовательскую проверку счётных ветвей в `market_link.py`. Краткая карта правил и границ: [`docs/AUDIT_INTEGRATION.md`](docs/AUDIT_INTEGRATION.md). Публичная версия содержит только вымышленные тестовые купоны. `AuditLedger` сейчас существует только в памяти и не даёт права на реальные ставки. Для тестов: `TEST_SEFIROT.bat` либо `py -3 test_sefirot.py`.

## Локальный сбор наблюдений (v0.6)

`CaptureJournal` записывает на диск хешированную последовательность одного матча: спортивный снимок → независимый probability seal → котировка и внешний сигнал (после seal) → расчёт → отдельное теневое решение. До появления честной истории для расчёта вероятности CLI собирает **только спортивные снимки**; следующие записи выполняются через Python API после реального расчёта. Пример ручного снимка в PowerShell (подставьте фактический источник, матч и время):

```powershell
py -3 scripts/capture_snapshot.py --journal data/match_001.jsonl --match-id match_001 --kickoff 2026-10-01T19:00:00+03:00 --home "Team A" --away "Team B" --source "https://example.org/actual-source" --published-at 2026-10-01T12:00:00+03:00
```

Пример адреса и команды выше — **заполнители**, а не реальные спортивные данные. Без `--confirmed` имена команд отмечаются `ASSUMPTION` и модель их не принимает; с `--confirmed` вы вручную заявляете проверку источника, автоматического подтверждения нет. Время публикации вводится вручную и не доказывается журналом. Файл фиксирует локальное время получения, которое может быть неверным, если часы компьютера неправильные. Один матч — один файл; не публикуйте в журнал персональные данные или секреты. `CaptureJournal(path).read()` проверяет повреждения и порядок. Хеш-цепочку можно целиком переписать вместе с файлом: для независимого доказательства времени нужна внешняя заверенная копия контрольного хеша. После аварии оставшийся `.lock` удаляется вручную только после проверки `.jsonl`; одновременный процесс записи получает ошибку.

Журнал не заполняется старыми аудиторскими купонами задним числом. Текущая CLI-команда сохраняет спортивные данные; вероятность рассчитывают и запечатывают отдельно через API после подтверждения достаточной истории. Никакой экран ввода ставки и LIVE здесь не создаётся.
