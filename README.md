# SEFIROT CORE 2.4.2 — исследовательская feature-ветка

**Основа дальнейшей работы — ветка `core242-version-audit`, CORE 2.4.2.**
Выбирайте её при клонировании и скачивании ZIP. `main` пока содержит 2.3,
а `core24-decision-finalizer` — 2.4.0. Перед продолжением сверяйте версию
в `src/sefirot/contracts.py` и `pyproject.toml`; порядок работы закреплён
в [AGENTS.md](AGENTS.md) и [HANDOFF_CORE_24.md](docs/HANDOFF_CORE_24.md).

Самостоятельная локальная Python-программа для прематчевого анализа футбола. Работает без интернета, API-ключей и сторонних библиотек. Основной запуск — **`sefirot.py`**. Старые `run_sefirot.py` и `SEFIROT_CORE.py` сохранены только для совместимости с прототипами.

Программа реализует полный локальный цикл: спортивные сведения → независимый прогноз → коэффициенты → проверки → допуск/риск → журнал → результат → Brier/калибровка → контроль компетенции. Это проверенная программная сборка, **не доказательство прогнозного преимущества**. В поставке нет сертифицированной на реальных невиденных матчах модели: демонстрации закономерно выдают PASS. Ветки BET и условного допуска существуют и проверены на контролируемых тестовых данных. В CORE 2.1 добавлен необязательный импорт котировок 1X2; реальный поставщик не проверен без ключа. В CORE 2.2 добавлена явная односторонняя выгрузка журнала в частный Postgres, которая требует настроенных пользователем секретов.

CORE 2.4 продолжает актуальный GitHub CORE 2.3. Добавлены SoS в вероятности, обучаемые командные пороги 0/1/2/3+, профильные priors, отдельный holdout стресс-класса и согласованный settlement/audit. Старый BASELINE_V1/STRICT остаётся стандартом; новая политика включается отдельно. Исторический TEST дал смешанный результат и не разрешает продвижение или денежный допуск. [Реализация P0](docs/P0_UPGRADE_CORE_24.md), [проверки и результат](reports/P0_UPGRADE_REPORT.md), [контекст для следующей сессии](docs/HANDOFF_CORE_24.md). LIVE не добавлен; Конституция сохранена.

CORE 2.4.2 устраняет дефекты, воспроизведённые при сравнении 16 архивных сборок: старые/отключённые/заменённые факты больше не закрывают проверки расхождения и движения цены; запись исполнения использует ту же допустимую PUSH-тройку, что и решение, и требует совпадения сборки и политики. Числовые пороги допуска сохранены. [Проверка версий и исправления](docs/CORE242_VERSION_AUDIT.md).

CORE 2.4.1 объединил P0 и итоговую карточку CORE 2.4. Сохраняются исправления смешивания калибровочных контрактов, невозможного PUSH, ограничения внешних ID и зависимости fitted-артефактов от CLI/API-кода. Карточка и sizing учитывают границы текущего режима STRICT/GRADED. Старые калибраторы требуют нового расчёта; старые денежные допуски не переносятся. [Исправления 2.4.1 и совместимость](docs/CORE241_DEFECT_FIXES.md).

## Windows: запуск без команд

1. Установите Python 3.11 или новее. При установке отметьте **Add Python to PATH**.
2. Скачайте ZIP проекта и **распакуйте целиком**.
3. Откройте `START_SEFIROT.bat`: он запустит весь синтетический цикл и покажет результат.
4. `TEST_SEFIROT.bat` запускает автоматические тесты. При ошибке он возвращает ненулевой код.

BAT-файлы сами переходят в папку проекта. Не нужно запускать Python из `C:\Users\имя`, где исходников нет.

Из PowerShell в папке проекта:

```powershell
py -3 sefirot.py demo
py -3 test_sefirot.py
py -3 sefirot.py --help
```

На Linux/macOS замените `py -3` на `python3`. Установка через pip не нужна. При желании доступен пакет `pip install .` и команда `sefirot`.

## CORE 2.4: конкретное финальное решение

В каждой записи `decide` теперь есть `decision_card`: конкретный допущенный рынок либо PASS с причиной, лучший численный кандидат для проверки, Base/Low/stress EV, WIN/PUSH/LOSS, точные пороги цены и альтернативы из заранее запечатанного пула. Отдельно различаются отсутствие value, хрупкая цена, нехватка данных/валидации, необходимость пересчёта и ограничение риска. Это причины существующего BET/PASS, а не новые разрешения ставки.

```powershell
py -3 sefirot.py demo --text
py -3 sefirot.py --db data/sefirot.sqlite decide ID quotes.json recheck.json --bankroll 1000 --peak 1000 --text
py -3 sefirot.py --db data/sefirot.sqlite explain DECISION_ID --text
```

`selected_market` заполнен **только при BET**. Предварительный отбор при заблокированном допуске хранится отдельно как `screened_market`; `research_candidate` не является рекомендацией. Команда `explain` читает сохранённую карточку без перезаписи и без новых расчётов по сегодняшним данным; для решений старых версий без карточки нужен их исходный код.

Две инженерные доработки: отбор допущенных рынков теперь сравнивает Low EV → stress EV → Base EV, после спортивных проверок; расчёт размера ставки использует допустимое худшее распределение WIN/PUSH/LOSS вместо несогласованных покомпонентных нижних границ. Вероятностная модель не изменена. Политика `research-policy-v3` фиксирует новый порядок; старые approvals/calibrators/holdout не переносятся в новую версию автоматически.

Отрицательный стресс остаётся veto денежного допуска. Порог коэффициента снимает только ценовые ограничения: он не отменяет составы, калибровку, факт-конфликт, divergence, свежесть и риск. Гарантии превосходства над 2.3 на реальных матчах нет. Точная карта изменения и следующего эксперимента: [CORE24_DECISION_FINALIZER.md](docs/CORE24_DECISION_FINALIZER.md).

## Анализ своего матча

Программа читает локальные JSON, а не самостоятельно подтверждает достоверность сайтов. Поставщики данных должны сохранять происхождение, время наблюдения, публикации и получения. Контракт и пример: `docs/INPUT_CONTRACT.md`, `examples/core2_case.json`.

Первый шаг намеренно принимает **только спортивные данные** и заранее объявленные рынки:

```powershell
py -3 sefirot.py --db data/sefirot.sqlite capture sports.json --markets markets.json
```

### Дополнительный источник коэффициентов 1X2

После `capture` можно получить котировки через The Odds API v4. Зарегистрируйте свой ключ у провайдера и задайте его **в переменной окружения**, не вписывая в код и Git:

```powershell
$env:SEFIROT_ODDS_API_KEY = "ваш_ключ"
py -3 sefirot.py --db data/sefirot.sqlite odds-events ID_ПРОГНОЗА --sport soccer_epl
py -3 sefirot.py --db data/sefirot.sqlite fetch-odds ID_ПРОГНОЗА --sport soccer_epl --event-id ID_СОБЫТИЯ --bookmaker pinnacle --region eu --rules-confirmed --output data/quotes-001.json
```

Проверьте у выбранного букмекера расчёт именно за 90 минут **перед** использованием `--rules-confirmed`. ID события показывает первая команда только при точном совпадении названий команд и времени начала с уже запечатанным прогнозом. Вторая команда записывает полную линию 1X2 и файл `data/quotes-001.json.receipt.json` с происхождением, временем и маржой. Для `decide` передайте `data/quotes-001.json` и отдельную предматчевую перепроверку спортивных фактов; импорт котировок не подтверждает факт наличия цены в аккаунте или возможность её исполнения. Пустая, запоздалая, неполная или отличающаяся линия отклоняется. Не пересылайте ключ через аргументы командной строки.

Провайдер содержит ряд европейских букмекеров, но **Parimatch 24 в его опубликованном списке отсутствует**. Это исследовательская цена другого букмекера; перед ручной ставкой цену нужно сверить с доступной вам линией. Бесплатный список событий не содержит цен; запрос котировок может расходовать лимит API. Для основных рынков без проверенного контракта поставщика используйте ручные JSON и обычный `decide`. LIVE и автоматическое размещение ставок отсутствуют.

Сохраните выведенный `id`. После фиксации прогноза загрузите актуальные котировки и перепроверку:

```powershell
py -3 sefirot.py --db data/sefirot.sqlite decide ID quotes.json recheck.json --bankroll 1000 --peak 1000
```

Новый факт требует `capture ... --parent ID --reason NEW_INFORMATION`; старое решение остаётся в журнале. Изменение одной цены требует нового `decide` на прежней вероятности.

После матча:

```powershell
py -3 sefirot.py --db data/sefirot.sqlite result result.json
py -3 sefirot.py --db data/sefirot.sqlite closing MATCH_ID closing.json
py -3 sefirot.py --db data/sefirot.sqlite report
py -3 sefirot.py --db data/sefirot.sqlite replay DECISION_ID
py -3 sefirot.py --db data/sefirot.sqlite verify
```

Все команды с ошибкой заканчиваются `ERROR / PASS`, а не разрешением ставки. Синтетические примеры помечены `synthetic: true`; отдельно поставляется явно обозначенный ретроспективный набор из аудитов. Ни один из них не открывает денежный допуск.

## Реализованные функции

- Девять логических сефир в одном процессе, без множества ИИ-агентов.
- FACT / INFERENCE / ASSUMPTION, зависимые источники, подтверждённые составы, противоречия, устаревшие и будущие данные.
- Историческая модель голов без коэффициентов; распределение счёта, чувствительность к сценарию; Low/Base/High после отдельной калибровки.
- 1X2, двойной шанс, DNB, целая/половинная фора, тотал, ОЗ, индивидуальный тотал. Возвраты учитываются отдельно от выигрыша/проигрыша.
- Implied probability, полная 1X2 маржа, fair odds, edge, EV, границы EV по совместимым вероятностям.
- Тактическая доказательная база, расхождение с рынком, движение линии, дополнительное независимое подтверждение, death-test, выбор более чистого рынка из ограниченного пула.
- `playable`, `playable with conditions`, `skip`, `unplayable`; A/B/C/D/RED; итог BET/PASS. Все критические блокировки имеют приоритет над рейтингами.
- Предматчевая перепроверка и пересчёт с ограниченным числом ревизий.
- Фиксированная доля банка с понижающими ограничениями, потолки ставки/матча/дня/общего фактора, снижение риска при просадке, запрет повторного риска на матч.
- Неизменяемые записи SQLite, атомарные транзакции, хеш-цепочка, повтор решения на сохранённых входах и версии кода.
- Результат → ошибка → Brier → reliability bins → калибровка → holdout; все PASS учитываются в статистике.
- Контекстные рейтинги сефир, WEAK/FROZEN, восстановление после исправления и новых тестов, сравнение версий и контролируемый откат.
- CLV по той же линии и букмекеру; отдельный учёт фактических ручных исполнений, доходности и нарушений правил.
- Хронологический backtest, который явно отличается от проспективного невиденного теста.

## Автоматическая локальная обработка

`py -3 sefirot.py --db data/sefirot.sqlite work data/inbox --watch` проверяет входную папку каждые пять секунд. Поддерживаются задания CAPTURE, DECIDE, RESULT, CLOSING с уникальным ID. Повтор выполненного ID не выполняет действие заново, изменение его содержания отклоняется. Остановка — Ctrl+C. Поставщик должен создавать JSON атомарно. Inbox не умеет одобрять политику или исполнять ставки. При аварии допускается повтор обработки; уже сохранённые прогнозы/результаты не переписываются.

## Проверки и границы

`docs/AUDIT_TRACEABILITY.md` связывает каждый пункт исходного аудита с реализацией и тестом. `docs/FINAL_AUDIT.md` содержит найденные дефекты, исправления и остаточные ограничения. `reports/TEST_REPORT.md` содержит фактически выполненные проверки.

Параметры `config/research_policy.json` — предложенные исследовательские значения, а не утверждённые пользователем или доказанные на реальном рынке пороги. Одобрение политики не заменяет независимый holdout. Обучающие, калибровочные и тестовые назначения фиксируются заранее; синтетический/восстановленный backtest не открывает денежный допуск.

Не реализованы по фундаментальному аудиту: LIVE, догон, экспрессы, малые рынки. Четвертные азиатские линии, специальные правила БК, дополнительное время также отклоняются.

Автоматическое размещение ставок отсутствует. Решение BET — аналитическая рекомендация; команда `execution` только записывает уже совершённое человеком действие. Источники/составы не проверяются у провайдера автоматически. Частная схема развёрнута в Supabase-проекте `kxqpwgwihtjmqlcxgfxp`; SQLite остаётся авторитетным локальным журналом. Проверки и ограничения — в `docs/SUPABASE_DEPLOYMENT_REPORT.md`. Tavily по текущему запросу пользователя не используется.

## Необязательная выгрузка журнала в Supabase

Программа работает без сети. Для частной резервной копии владелец базы может отдельно включить доступ роли `sefirot_ingest` и выполнить **явную** одностороннюю выгрузку. Облачная роль создана без права входа (`NOLOGIN`); её требуется активировать с новым паролем вне репозитория. Программа никогда не создаёт ставку и не переносит облачные данные обратно в SQLite.

1. Установите дополнение: `py -3 -m pip install ".[sync]"` в корне проекта. Для обычного запуска оно не требуется.
2. В настройках Supabase Database → SSL Configuration скачайте CA сертификат проекта. Администратор БД отдельно задаёт роли `sefirot_ingest` право `LOGIN` и уникальный пароль; храните пароль локально, не в Git и не в истории команд. Используйте строку подключения **Session pooler** (порт 5432) с именем `sefirot_ingest.<project-ref>`; прямое соединение возможно при доступном IPv6. Роль имеет только SELECT/INSERT в частной схеме. Настройку роли и сертификата уточняет `docs/SUPABASE_DEPLOYMENT_REPORT.md`.
3. В своей PowerShell-сессии задайте `$env:SEFIROT_SUPABASE_DB_DSN` и `$env:SEFIROT_SUPABASE_CA` (путь к скачанному `.crt`). Не помещайте пароль в командную строку `sefirot.py`, конфигурационные файлы репозитория или сообщения. `.env.example` — только перечень переменных; приложение его автоматически не загружает.
4. Сначала проверьте локальный журнал: `py -3 sefirot.py --db data/sefirot.sqlite sync-supabase --check-local`. Эта команда не требует облачных секретов. Затем запустите `py -3 sefirot.py --db data/sefirot.sqlite sync-supabase`. Команда считывает существующий локальный файл без создания нового, проверяет SQLite, все 22 таблицы и цепочку аудита; затем в транзакции дописывает отсутствующие строки и сравнивает каждый облачный ряд. Повторный запуск безопасен. При несовпадении транзакция откатывается и команда выдаёт `PASS`. Вывод содержит хеш снимка и вершину цепочки; сохраните его отдельно, если требуется внешний контроль целостности.

Пароль для этой роли здесь не настроен, поэтому реальный запуск CLI против облака пока **не подтверждён**. Проверены локальный протокол и права роли в реальном Postgres, включая откатываемую пробную вставку. Подробности: `docs/SUPABASE_DEPLOYMENT_REPORT.md`.

## Структура

- `src/sefirot/` — текущее приложение CORE 2.4 feature;
- `src/sefirot_core/` — прежнее ядро, сохранённое для совместимости;
- `tests/` — тесты обоих поколений;
- `config/` — явно версионированная политика;
- `docs/` — архитектура, поток, карта сефир, требования и аудит;
- `examples/` — синтетические примеры и отдельно помеченный ретроспективный аудитный набор;
- `data/` — ваши локальные журналы; исключены из Git;
- `reports/` — проверка сборки без личных данных.
- `schema/` — снимок схемы Supabase для установки в **новую** базу; к существующему проекту повторно не применять.

## P0: диагностика исходных 312 ставок
